# 对白生成与后期配乐

人物音色参考与试听确认单独遵循 [人物与声音流程](character-voice.md)：每人独立YAML，只有剧本需要说话才要求配声；无台词/非语言声不触发。需要说话但未选声时继续独立工作，末尾集中试听；音色确认不等于最终台词或混音验收。声音参考不能用配乐代替，显示名不自动变为台词称呼。

本文件落实用户2026-11-10要求：分段生成音乐会在连接处重启或断裂；以后视频生成只保留说话，音乐由后期根据完整剧情制作并插入。根规则保存偏好与授权，本文件维护声音流程；职责由`skill-routing.md`维护。此规则更新不等于当前片已重混，也不启动付费任务。

## 1. 生成阶段与后期分开

- 新原创视频默认只生成已写明的对白。无对白镜头默认静音；不得自行加入旁白、歌曲、哼唱、音乐点缀、环境声或音效。用户明确需要的环境声/音效属于例外，应分项记录；无配乐不等于禁止已要求的人声。
- 视频英文提示词只写该次要生成的声音，明确禁止配乐。剧本或分镜中的后期音乐意图保存在配乐方案，不编译成视频模型的配乐要求。总审计和提示词二次审计均检查这一区分，清除上游模板的背景音乐、渐强弦乐等残留。
- 接口有独立音乐控制字段时使用经核实的字段；没有时用英文提示词约束并在结果中检查，不虚构`music=false`等参数。若只有总音频开关，不能为了禁BGM关闭对白。音乐参考也不作为视频生成音频输入；明确的对白参考按真实入口使用。
- 原片换角/复刻且要求保留原声时保留原声，不用新默认改写原任务；已提交配置与已生成文件保留。仅规则维护不批量改历史提示词。

## 2. 先做全片配乐布局

剧本/分镜阶段写配乐意图，取得真实剪辑后再落精确时间。助手在既定创作范围内判断，不要求用户逐镜指定音乐；不把音乐当每段生成的必填项。

| 叙事需要 | 可采用的配乐处理 | 需要避免 |
|---|---|---|
| 观众需要直接感受犹豫、孤独、脆弱或重要对白 | 留白、延迟进入，或极稀疏且低强度的器乐 | 从开头就铺满情绪、盖住气口与对白 |
| 累积威胁、关系发生变化、行动逐步形成 | 在具体事件后进入，随事件改变织体、节奏和强度 | 每个生成段重新起曲、未发生转折便提前煽情 |
| 关键决定、关系确认、情绪释放 | 延续已有主题，在决定后展开并给尾音空间 | 每次切镜都换音乐、结尾无音乐句法地硬切 |
| 剧情需要突然抽离、危险或清晰听见一句话 | 明确切出/减弱音乐，保留必要对白；说明是否要真正静音 | 把“无音乐区”当作删除所有音轨 |

这些是判断示例，不是强制情绪公式。全片无音乐也可成立，须记录理由。

每个cue必须写：用途与不配乐理由（如适用）、入点/出点及事件触发、情绪和强度变化、配器/音色、节奏倾向、是否承接前后主题、对白避让、淡变，以及对应剪辑版本。另列明确无音乐区间，不能只在有音乐的位置填表而遗漏留白设计。

以**剪辑后全片时间**为坐标，入点包含、出点不包含；不能用各生成段局部0秒替代总片坐标。登记视频路径/哈希、时间基、真实时长；剪辑更改后由时间映射重新校准cue、对白区间及淡变，旧方案标失效，不机械平移猜测。

## 3. 单独制作音乐

- 默认器乐、无歌词、无哼唱；人物对白由原视频/对白底轨持有，不在音乐文件里重生成。用户明确要歌曲时另定。
- 一个情绪段落可跨多个镜头和生成段。优先制作覆盖完整所需区间、留足起落/尾音的音乐，再按音乐句法剪辑；可用多个相互协调的cue，不要求全片只有一首，也不按视频段数决定曲数。不得自动拉伸、硬循环或用交叉淡化掩盖明显节拍/调性冲突。
- 音乐提示词用英文，说明用途、配器、情绪进程、节奏、时长/尾音和无人声要求。模型不支持的结构或精确时长写为设计目标并实测，不能假称参数生效。交付/提交前二次审计其与cue、对白和画面节奏是否一致；无人物/机位参考的音乐任务注明那些检查项不适用。
- 生成服务/本地模型需核实实际入口、输入输出类型、长度、器乐控制、授权范围及本机资源。API/工具没有接入时标待实现或待核实，不用语音合成、音画融合、素材上传入口冒充音乐生成。必要的用户素材可直接复用；保留来源与使用约束。
- 音乐文件作为`materials.yaml`内`kind: audio`资产登记，附真实路径/哈希及状态；任务来源、提示词版本、模型/实际参数和音频检查记录可保存在独立生成记录，由资产ID引用。不要扩写现有materials的生产协议或建立第二套资产状态。成品归档到`projects/<作品>/02-素材/音频/`，中文语义命名，例如`配乐-彼此依靠-版本01.wav`。

## 4. 混音与旧片处理

保留独立对白底轨、音乐源文件和无配乐视频；新混音另存版本。制作时可用独立轨/总线，默认播放的成片音轨须包含实际混合后的对白与音乐，不能仅封装成两个互斥的可选音轨就称为已混入。

- cue指定音乐资产、素材入点、全片入/出点、增益、淡入淡出及音量包络。音乐不足以覆盖区间时明确补作/改布局，不静默循环或变速；必要重复需确认音乐句法与连续性。
- 音轨序号从0开始：源视频声音用`dialogue.audio_track`，独立对白底轨用`dialogue.stem_audio_track`，音乐用各`cue.audio_track`。实际使用的输入只有一条音轨时可省略；多轨必须明确选择，工具不推测默认对白或静默取第一轨。混音记录保存所选音轨、输入路径及SHA-256；未使用的源视频声音由原片保留。
- 完整剪辑按源媒体PTS的0秒计时，复制的视频保持原PTS；对白按同一时间原点对齐，不能把音轨相对首个视频帧裁切后却保留原视频起点。音乐素材入点也按该素材原PTS解释。源片存在起始空白时保留其时间位置，不用混音偷偷剪掉；需要调整时间线时先剪辑并重新核实配乐布局。
- 方案、视频、清单以及实际使用的每项音乐/对白素材都检查作品归属；不能通过同作品清单引用另一已登记作品的媒体。跨作品复用应先按素材导入流程归档至当前作品，再引用该路径。
- 导入目标及记录路径按实际解析后的作品归属检查，目录联接不能把写入重定向到另一作品。混音与器乐制作记录使用完整媒体文件名（例如`成片.mp4.混音记录.json`），不同容器分别留证；已有记录或并发占用时拒绝覆盖，旧记录仍可通过明确路径读取。
- 音乐导入先取得作品级资产锁，再取得素材清单锁，所有入口保持同一顺序；锁内重新读取并检查资产ID，再发布文件和原子登记。同作品的不同清单也串行处理，不能引用另一导入尚未完成登记的临时结果；同清单并行导入不同ID不会覆盖彼此，同ID只允许一次成功。登记失败时仅撤回本次新建且文件身份未被替换的音频，保留原始输入、已有去重素材及既有登记。进程强停后目标已存在而登记未完成时，相同内容哈希可用原参数恢复登记，不覆盖或删除该已有文件；不同内容仍拒绝。
- 混音先在作品素材树外建立私有临时快照，按真实源路径去重。计划、清单从快照解析，视频、对白底轨和每项音乐的校验、实际编码及发布技术核验均读取同批快照；记录保存原路径与实际消费字节的捕获SHA-256，不在导出后重新取原路径哈希冒充来源。发布前再次检查原依据，持续变化时拒绝发布；即使原文件在编码中被替换后恢复，编码仍只消费已验证快照。正常完成或捕获异常时清理本次临时快照；强制终止或断电遗留的私有临时目录只作缓存，不是有效素材。最终交付不保留重复媒体，原文件不修改。
- 音乐在对白、气口、重要信息处让位；可以按对白区间做音量自动化，也可用实际可用的侧链压缩。区间自动化将重复、重叠或相接区间合并，近邻区间的80ms淡变包络取最大避让量，不因多人对白重叠而重复叠加降幅。避免过度抽吸、盖字、音乐突然抬高；不能只凭统一dB值宣布对白清楚。
- 混音检查响度、峰值、削波、采样率、声道和音画起点，导出保持原播放速度。目标响度/峰值按用途明确，不能把单一固定数值当所有作品标准；处理器的实测报告与实际听音分别留证。
- 旧视频若对白和BGM已混在一个音轨：先识别是否有干净对白或可用分轨。分离只是候选修复，会损伤人声/环境；保留原片，实际听音检查后才能采用。不允许整轨静音丢对白、不直接叠加新音乐造成双配乐、不把提示词写了“无音乐”当源音轨已经干净。无法可靠分离时说明影响、可行替代及需用户决定的对白重做范围，不自动重配人物说话。
- 已是60fps且只更换/混入声音时，优先保留视频码流、只处理音轨；时间线没有变则无需重复补帧。新剪辑先完成音轨再补帧，水印按对应已确认方案放在补帧后；不增加未要求的水印。

## 5. YAML与功能交接

使用`templates/short-drama/配乐方案.yaml`登记声音策略、剪辑依据、有音乐/无音乐区、资产引用和混音/检查入口。它是**配乐记录与音乐.py工具输入契约**，目前不是`autodl run`的生成配置，不把空路径或空cue当成ready。

每个作品的`project.yaml`只引用这份方案、现有materials、当前混音配置/结果与问题记录，不复制cue或音乐资产状态。旧状态已归档，入口不与历史JSON双写。详细文件放该作品获认可的后期/声音目录，路径按目录与命名规范执行。

| 功能 | 要完成的行为与验收点 | 当前能力边界（2026-11-10） |
|---|---|---|
| 配乐布局 | 读剧本、分镜、真实剪辑和对白区间，给有乐/无乐范围、理由、进出触发和强度；剪辑变更使旧时间标失效 | Codex按本文件执行；YAML模板已提供，音乐.py已校验时间线和留白覆盖 |
| 音乐制作 | 以cue为单位准备英文提示词、调用真实音乐入口、记录task_id/来源、下载并检查音频，可复用用户音乐 | 支持导入及本地音符合成器乐草稿；专用AI音乐生成服务未接入 |
| 音乐插入与混音 | 插入/移动/替换/移除cue，设置素材入点、增益、淡变和对白避让；产出独立混音记录与可播放混合轨 | 音乐.py支持cue增删改配置、淡变、对白区间自动化与真实混合音轨；复制视频码流 |
| 预览与导出 | 网页试听完整上下文与所有音乐入出点/跨段接缝，保留无配乐母版及新版本，输出真实技术数据 | 审片.py提供本地网页、区间循环和版本哈希绑定；实际连续视听不足时保持待复核 |

工具实现必须验证：cue范围在真实时长内、入点小于出点、淡变不超区间、资产存在且已检查、来源长度足够、无音乐区不被非明确淡出尾音覆盖、cue重叠有混音目的、剪辑哈希匹配。缺输入不得生成假音轨或覆盖原片。

## 6. 交付顺序与验收

对白视频生成 → 剪辑与全部接缝处理 → 校准配乐布局 → 单独制作音乐并混入 → 补帧 → 按要求水印 → 网页音画审片。

审片检查整片情绪弧线、每个音乐入点/出点、跨镜/跨生成段的连续、所有对白的可懂度以及无音乐区域是否成立。技术检查、ASR和静态波形不能证明音乐好听或听清了对白；未实际听音标待复核，用户指出音乐不连续时登记该版本声音不通过，不继续沿用原通过结论。

完整作品已授权的后期按当前范围推进，不重复要求用户逐cue确认；只有实质创作分歧、真实入口/账号阻碍或超出现有范围时才询问。单独需求/规则调整不生成新音乐、不修历史作品；用户随后明确要求修当前片时从现有素材和问题记录继续。

工具命令与当前支持字段见 [视频工具](../../tools/视频工具/README.md)。混音当前支持 none/regions 对白避让；不将模板中的未填写项当作已实现的自动音乐生成或自动听音判断。
