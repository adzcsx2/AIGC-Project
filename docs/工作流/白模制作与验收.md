这是原创与复刻白模的共享执行规范。先读作品 `project.yaml` 与当前已选文件；按 `docs/skill-routing.md` 进入原创或复刻技能。环境与来源见 [Blender接入](../工具与接口/blender-integration.md)，异常按 [故障排查](白模故障排查.md) 定位。上游原文只供追溯，不作另一套默认规则。

### 原默认先做白模

用户2026-11-10明确要求：以后所有视频制作，没有特定要求都先做白模。新创作、续段、指定段重做和动作迁移在已确认剧情/初步分镜后，正式生成前默认完成简单几何预演；已有合格白模直接核对复用。用户明确要求跳过白模或另定制作流程时按其要求记录，不把“镜头简单”“只有表情”“采用首尾帧”“指定某API”自行解释为免预演。

- 先确定并验证主体数量/体积、世界布局、相对轨迹、接触锚点、节奏及真实摄影机。汇聚入眼等光学转场补低分辨率转场预演，区分相机运动、图层/曲面映射与物体自身运动。只做完成任务所需的圆柱等基本体，不增加精细角色、骨骼步态或表情建模。
- 保存工程后独立检查，完成双版预览及与实际能力相符的动态/可读性复核；最终秒数、镜头范围和端点依预演修正。技术测量不能冒充自然表演或用户认可，也不因默认先白模新增一轮无依据的收费/审批确认。
- **预演用途与接口输入分开。** 保留白模运动/摄影的换角按真实titim契约绑定ref_video；首尾帧或参考图入口可将预演用于设计、端点与审计，但没有ref_video字段就不能声称已上传白模控制。若需改接口才能满足动作控制，先核实并说明，不静默切换。
- 只查询/恢复既有task_id、下载、纯剪辑合成、补帧、音轨处理及规则维护不创作新镜头，不倒补白模；已接受历史片段保留，仅预演本次新增或重做范围。只问是否需要白模先交判断，不把提问本身当制作或付费生成授权。

`project.yaml.whitebox_plan`绑定实际制作计划。总审计记录白模工程/预览/检查依据、复用或用户明确例外；缺白模且无适用例外时保持待补，不能直接交生成提醒。

## 先确定白模要负责什么

| 输入 | 负责 | 检查边界 |
|---|---|---|
| 剧本/原片 | 事件、动作因果、摄影目的、原片需要保留的时间与声音 | 原创依已确认稿；复刻区分实看事实与隐藏部分估计 |
| 可编辑白模 | 简单占位的世界空间、数量/比例、朝向、主体与道具轨迹、接触锚点、摄影和切点 | 必要位移/高度/接触关系必须实际制作；不制作精细身体与关节表演 |
| 人物/场景/道具参考图 | 身份、形制、材质与已选风格 | 身份板背景与静止姿势不自动覆盖动作；场景图保留当前空间锚点 |
| 模型提示词 | 占位到角色的映射、相对尺度、自然步态/肢体/表情、材质及接触反馈 | 新正文英文，按真实容量落实；简单占位路线不能省略所委托的动作，不能直接塞上游中文15节模板 |

白模和图片冲突时先检查来源是否选错，再明确各自控制范围。不能要求模型自行解决人数、尺度、路径、接触关系或机位等实质矛盾。按用户2026-11-10要求，今后新做或修改白模只用以圆柱为主的简单几何占位；历史复杂工程保留，不作为恢复精细建模默认的依据。已有合格外部引导仅使用、不修改时无需为规则更新重做。

This supplements, rather than replaces, the normal-speed and actual1× playback checks.

- 白模负责大尺度路径、方向、速度变化、升降和接近→接触→分离时序；视频模型负责自然迈步、髋肩协调、爪抓/拍翼、承重细节、面部情感和材质。纯圆柱沿地面平移是有意的路径代理，不把它评为已完成真实走路，也不为消除“滑柱”重建四肢步态。
- 接触必须有可检查的几何关系：爬树代理贴近树干且按剧情真正升降/绕行；飞扑代理有离地、接近和被接住的路径；抱转有双方相对位置与共转，贴脸有相应接近和小幅相对运动。爪、手、脸和软组织的具体动作与物质反馈写进英文提示词，未建出的细节不冒称白模已验证。
- 每份请求分别写明“保留的空间/摄影”和“由模型补全的细节”；不得要求逐帧保留圆柱的刚性身体动作，同时又要求自由自然步态。不能靠提示词掩盖错误高度/路径或漏做镜头，也不把文字补全承诺成接口的强制控制能力。
- 总审计核对真实引导、参考图及英文正文一致；输出后沿现有技术、风格、接缝与用户审片规则验收。代理可读性通过不等于龙体型、爬树、表情或物理反馈已通过，不自动付费重抽。

## 制作顺序

### 1. 时间轴与约定

复制 [白模计划模板](../../templates/whitebox-retargeting/白模计划.yaml)，填写真实来源。计划中的文件路径统一相对作品根目录，和生成配置的相对路径基准不同。

- `shots` 是画面中的摄影镜头；`generation_shot_id`可选，引用materials中的生成片段。多个摄影镜头可属于一次请求；本地检查不需要填写生成片段。
- 时间使用零起算帧区间 `[start_frame, end_frame)`，相邻镜头连续覆盖 `frame_count`。例如24fps的0至96帧就是4秒；Blender原生帧号为 `frame_start + 帧索引`。
- `fps.num/den`保留有理帧率。秒数转帧时在制作说明记录舍入方法；相机切换、提示词时间、切片与检查都由同一表派生，不能独立手填多套时间。
- 复刻保留源片时序，必要时记录源PTS到白模帧的映射；VFR原片不能只用平均fps推断全部事件。不得为套模板增加镜头、改速或冻结末帧。
- 定义世界轴向、尺度、角色正面与接触锚点。屏幕左右由实际相机投影确认，不能认为世界+X永远等于画面右，也不强制所有机位正对同一面墙。

### 速度与真实物理时间

用户2026-11-11指出五秒幼龙测试像慢动作，要求以后白模必须注意速度。本节适用于新做/修改白模及复用前的适配检查；具体病例数值不作为所有动作的固定模板。

- **默认正常速度。** 先区分步行/奔跑、地面发力、无动力腾空、持续拍翼/推进、受外力托举等机制，再按作品物理与当前动作确定时间。用户明确慢镜、时停、悬停、特殊重力或要求保留原片速度时遵从，并记录范围、倍率或持续受力依据；不把所有腾空机械改成自由落体。
- **片长与动作时长分开。** 按实际路径长度、体量、发力与接触设计启动、主动作、最高点经过、落地/碰撞、缓冲和恢复的秒数，再换算成实际帧号。不为API最短时长或“看清动作”把很短的起落拉成秒级悬浮；剩余时间用于已确认的准备、情感反应或结果，不擅自加剧情、静止垫长或整体变速。
- **检查速度曲线，不只看端点。** 记录单位、实际fps/PTS和阶段时间；用位移/实际秒数估算速度，复杂或变速路径逐帧求值检查速度/加速度趋势。重心轨迹、身体尺寸与最低足间隙分别量，四肢收放不能被当作重心升降或实体伸缩。摄影机速度与主体世界速度也须分开。
- **插值服从动作机制。** 不能对所有关键帧统一套缓入缓出、AUTO_CLAMPED或峰顶平台。无持续升力的腾空在顶点仅瞬时竖直速度为零，应连续转入下落，不能无因定高或落地前缓慢刹停；接地后的腿部/身体缓冲与草泥反馈按顺序发生。拍翼、推进或外力支持慢升/悬停时，明确其持续作用、失效和恢复，不用一句“真实物理”解释缺失的受力。
- **物理估算只作适用条件下的基准。** 近地、忽略阻力、无动力、起落同高时，可由重心上升量h估算t上升=√(2h/g)、总腾空时间=2t上升；最高点不应有有限时长平台。这里的h不是任意姿势的脚下间隙，g也服从作品设定，不能把个别厘米数/秒数设为所有角色的硬限制。[物理依据：NASA弹道方程](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/ballistic-flight-equations/)。
- **送模版原速复核后放行。** 按实际1×播放完整预览/送模版，核对启动、速度变化、顶点、接触和缓冲是否有重量与节奏，不能只看抽帧、几何包络或最高点。分开记录空间/尺寸检查、速度/物理检查和生成后的执行效果。现有白模工具的checks_passed不自动证明动力学或自然表演；适用的速度/物理项未通过，先修白模及对应正文再复核，不将错误引导交模型“用文字改正常”。
- **检查时间基准与尺寸判断。** 编码/补帧前后核对帧率、帧数、PTS、真实时长及同一动作相位，不能改fps标签、重复帧或变播放速度冒充正常物理。固定机位下比较同姿态的体高/头身参照；起落时抬头、直立、展翼及透视会改变外框，颜色分割外框不能直接证明3D体积放大或恒定。白模通过不保证生成端遵循，成片仍按原速和同一尺寸/高度定义检查，不自动收费重抽。

### 2. 简单占位、路径与摄影机

先确认布局、主体比例、朝向与最大动作范围，再给简单占位制作位移/朝向关键帧、必要的道具路径和接触锚点。身体结构由角色参考与提示词承载，不建人类/四足/翼的完整关节系统。预测最终四肢、翅膀或兵器的最大展开，在白模构图中为其预留空间；只让圆柱刚好入画不算动作覆盖合格。

摄影设计由 `storyboard-camera` 承接现有分镜，具体职责以路由表为准。每镜在现有分镜/运镜审计中记录以下控制数据，再由Blender技能写入实际工程，不另建竞争时间轴：

| 控制项 | 必须明确并落地的内容 |
|---|---|
| 镜头语言 | 观众要看懂什么、跟随哪个主体、景别及起止构图；固定镜头也写清用途 |
| 机位与角度 | 世界坐标/相对主体位置、离地高度、朝向/俯仰/侧面关系、地平线与轴线；相机和目标分别运动 |
| 成像与取景 | 透视或正交、焦距/视场、传感器和实际画幅；区分移动摄影机与变焦，不用缩放主体冒充推拉 |
| 路径与节奏 | 起止帧、路径/关键点、跟随或注视目标、相对距离、速度趋势及缓入缓出；持续动作不过度停顿 |
| 切镜与承接 | 实际启用的Camera、切换帧、切出触发、下一镜承接位置/运动方向；不靠提示词新增未制作镜头 |
| 覆盖与证据 | 最终动作展开余量、遮挡窗口、关键接触可见范围；逐帧相机数据、代表帧及完整预览 |

可用摄影机位置/旋转关键帧、父级控制器或跟随/注视约束实现设计，按当前Blender实际能力选择；记录实际相机与目标对象名。检查求值后的世界变换和投影，避免跟随约束造成翻转、突然变焦、穿过实体或关键互动被树干挡住。仅写`camera_motion: moving`不是已经控制了摄影机；该字段只声明检查意图，完整数值/动画在分镜与工程中。

看穿的门窗按当前渲染通道建真实开口；不要把实心“玻璃”或柜体挡住的主体误诊成焦距错误。焦距公式仅作初估，最终看实际相机、传感器、画幅、像素比例与求值后几何投影。主动作、接触、反应及必要支撑均在构图中可读。

### 3. 保存后独立检查

新工程默认用本机Blender后台Python；脚本归公共tools、参数归作品。使用 `--factory-startup`，不修改用户偏好、插件、启动文件。已有工程另存新版本。

保存工程后填写真实SHA-256，用 `白模.py inspect` 在全新进程重新加载磁盘工程。不能仅根据 `bpy.data.is_dirty` 认定内存与磁盘一致；直接RNA修改不一定可靠地置脏。GUI试验最终必须落到脚本/参数或已保存工程，并重新独立验证。

旧作品专用的 `检查喝奶白模.py` 与 `布置喝奶中世纪场景.py` 同样启动子Blender读取磁盘工程，保留调用方内存；明确已置脏的场景先拒绝。直接RNA修改即使未置脏，也不会被当成已保存来源。需要检查或使用这些修改时，先由调用方另存新工程，再按对应入口选择来源。

旧作品制作、检查与置景入口也要求真实 `project.yaml`。来源工程、动作配置和全部目标按最近作品入口核对归属，不能写入嵌套的其他作品。工程、JSON记录、预览图片和视频先写私有临时文件，再排他发布；即使构建期间出现同名文件也拒绝覆盖，已发布的部分结果保留为该版本的诊断材料。

`制作森林喝奶固定引导.py`的布局和底图合成两个阶段也独立重载所选磁盘工程，输入前后核对工程与底图哈希。来源、工程、帧目录、检查图片和记录均在首个副作用前解析真实路径并核对最近的`project.yaml`所有者；目录联接或嵌套作品不能将输出导向另一作品。全部目标预先检查占用，新工程以排他方式发布，不覆盖并发任务的文件。

现有检查器读取每帧实际相机、求值后网格及渲染可见性，检查声明的主体构图、固定/移动机位、接触锚点距离；需要遮挡检查时显式填写 `max_occlusion`。射线检查保留墙、柱和门框，仅排除当前主体自身、不可渲染对象；不靠名字跳过墙面。

当前限制：网格包围盒和有限表面射线不等于精确逐像素可见性或全部碰撞检查；支持常规网格、曲线及透视/正交相机。对象实例与外链Blender库须先在副本中本地化/实体化；未打包的外部文件（包括位移纹理）拒绝检查，先在副本中打包或清理不用的依赖。图像序列、影片及UDIM暂不支持，单帧打包不能证明完整依赖。几何节点、外部缓存、刚体及布料/流体/软体/动态绘画等模拟暂不支持，须转换为工程内可重播的网格/变换动画；不声称已穷尽外部缓存依赖。体积、蜡笔、点云、粒子、渲染区域裁切、Simplify和视口/渲染修改器或曲面细分设置不一致也会被拒绝。

检查器使用视口求值图，因此拒绝场景中对象或集合的视口禁用/眼睛隐藏（包括父节点及约束目标），不偷偷修改其状态；请在工程副本中取消这些视口隐藏，原有 `hide_render` 仍按渲染用途保留。每帧构图包含实际近/远裁切面，固定/移动机位比较完整相机投影及世界变换，包括传感器、相机类型和显示画幅。未声明的接触、语义动作或身体合理性仍需检查，不能把测量通过写成整片通过。

当前视图层必须是唯一启用渲染的图层，双版本与空间图显式渲染同一图层；其他图层可保留但必须关闭渲染。当前图层的集合 `Exclude`、`Holdout`、`Indirect Only` 及对象 `Holdout`、`Shadow Catcher` 暂不支持，检查会拒绝。不要只在测量时换层或解除遮罩来凑通过；先在新工程副本中确定可支持的可见性，再重新检查、渲染。

### 4. 双版本预览

同一已保存工程与时间轴导出：

- **审片版**：Workbench语义颜色、轮廓和镜头/帧标注，方便观察。
- **送模版**：无标注、描边和水印的简单纯色或灰度占位，检查主体区分、轮廓与关键接触是否可辨。当前 `白模.py render` 实现的是EEVEE灰度分支，以`model_gray`配置；审片版虽有语义色，不能冒称送模版保留了彩色。

两个版本都从同一工程重新加载，导出前比较逐帧几何与相机指纹。仅改变显示方法，不能偷偷改变人物数量、可见性、镜头或动作。当前灰度分支清除送模副本的材质覆盖，使各主体的`model_gray`实际生效；源工程中的覆盖材质保留。采用彩色送模时，须使用实际支持无标注纯色的导出实现，核对整段颜色映射、工程/时间轴/相机一致性及实际文件哈希，并明确记录相对默认灰度分支的变化；不能把带字审片版直接送模，不能伪造现有工具未支持的颜色字段或检查包。送模版仍要亲眼看，中性灰度并非强制审美或模型最佳设置的结论。

预览关闭景深与运动模糊以便定位结构问题。工具只在独立重载的导出副本中移除对应开关的关键帧、NLA通道和驱动，保留镜头焦距、机位及几何动画；逐帧求值和每次实际渲染后复查开关，复查失败的图片不发布。无法处理的动画结构、缺少支持的模糊开关，或关闭模糊后影响几何/相机指纹时直接拒绝导出，不换渲染器或清空整组动画绕过；磁盘源工程及其哈希保持不变。整段任何一帧出现可见文字对象都会阻止双版本导出，包括首帧隐藏而后续显示的标注，应在工程副本中清理。工具检查的是约定范围内的求值几何，不声称覆盖所有Blender渲染特性。

两版的显示属性按明确清单固定：sRGB/Standard、无Look、曝光0、Gamma 1，关闭颜色曲线、白平衡、显示模拟和抖动；输出使用场景颜色管理的8位RGB PNG，禁止透明背景、合成器、序列器、多视图和Freestyle描边介入。审片版固定Workbench语义色及仅镜头/帧标注；送模版关闭全部标注并清除当前图层的材质覆盖。上述属性仅在副本移除对应关键帧、NLA和驱动，逐帧及实际渲染后同时核对原始/求值状态；渲染中恢复标注、曝光或曲线同样会在图片发布前失败。其他动画保留，影响几何/相机的显示属性依赖须先在新工程副本解除后重检；不整体清空场景或相机动画。

先低分辨率完整预览，再按需要正式渲染。PNG序列保存在作品中间数据，编码由本机FFmpeg完成，检查帧数、时长与解码；编码显式采用工程像素比例，并验证输出尺寸和SAR，不继承PNG可能相反的像素比例标签。当前工具输出无声白模预览；原片音轨独立保留，进入替换接口前按现有流程恢复/绑定，不能用静音预览替代要求保声的引导。

首帧空间图和逐镜入/出点图用于定位；完整动态预览用于判断代理路径/高度、接触关系、摄影覆盖与连续性。自然步态、爪抓、表情和细致受力属于模型生成后的表现，不能用圆柱预演宣称通过。平面图只表示采样时刻，不证明整段运动或越轴已通过。

### 5. 检查、修正与交接

网页审片直接引用作品内两版视频。技术、静帧、动态、送模可读性、声音和用户认可分别记录。同一问题连续两轮没有改善，保存版本、说明可观察缺口和具体方案，不继续盲目渲染。

切点检测使用固定显式阈值、一对一时间匹配，分别报告缺切、多切和误差。解码失败直接失败；不得自动降低阈值凑数量。相似画面切换可能漏检，快速动作/闪光可能误检；`detected_match`只是检测候选匹配，仍须查看切点附近动态证据。

含多个视频流时，切点和PTS校验统一选择探测结果中的第一个视频流，记录 `video_stream_index`；FFmpeg不得自行换到分辨率更大或带default标记的另一流。需要核验其他视频轨时先明确另存所选轨，不把本记录当成其他轨的检查结果。

检查针对未剪改的对应时间轴；剪辑、变速、裁尾或补帧后需采用对应版本的时间映射，不能拿原始白模时间直接核验已改时长成片。默认白模/剪辑24fps，最终成片按现有规则处理60fps；中间白模不自动补帧。

已要求后续替换时读 [video-retargeting](video-retargeting.md)，核实真实titim槽位、主体检测、时长与音轨。用户已有授权沿用，不增加重复确认；本地检查不授予新收费生成或重抽权限。只有剧本需要说话时才检查角色音色，按 [声音流程](character-voice.md) 处理最后集中试听。

## 可执行命令

在仓库根目录用 `.venv\Scripts\python.exe tools/视频工具/白模.py`：

| 子命令 | 用途 |
|---|---|
| `validate 计划.yaml` | 校验字段、引用、工程哈希、时间轴；不声明场景通过 |
| `inspect 计划.yaml --version 01` | 全新Blender进程逐帧采样，只出证据 |
| `render 计划.yaml --version 02` | 检查通过后输出两版预览、关键帧和空间图 |
| `verify-cuts 计划.yaml 视频路径 --output 新记录路径` | 默认阈值0.28、容差2个计划帧；按素材显式调整 |
| `check-bundle 计划.yaml 检查包路径` | 重新核对计划、工程、程序及输出哈希 |
| `review 计划.yaml 检查包路径` | 建立现有网页审片会话，再用 `审片.py serve 会话路径` |

`--blender`可指定实际程序。命令的计划/检查包路径相对当前工作目录；计划内路径和verify-cuts的媒体/输出路径相对作品根目录，绝对路径也必须在同一作品内。版本占用时另取版本，不覆盖。检查失败返回非零状态、保留诊断和日志；不得跳过失败去提交生成。
