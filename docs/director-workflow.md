# 导演规则与技能分工

本文件落实用户于2026-11-09确认的整合方案。根目录 `AGENTS.md` 与用户最新明确要求优先。
项目有9个可调用技能；第三方原文在 `.agents/resources/` 按需取用，不作为第二套工作流入口。

## 从文案到制作

1. 先读用户文案、已确认决定和现有素材。识别原创、白模复刻、非白模原片复刻；白模不是使用导演技能的前提。
2. 文案不足时主动补成中文故事/动作草案。写明时长、人物意图、动作因果、反击、位移、节奏、结果和新增假设。
   给用户确认后才开始正式分镜、模型提示词、补图与视频制作。不能边等确认边推进这些依赖步骤。
   可以继续查已有素材和接口能力。用户已经提供完整明确文案或确认过此版时复用确认，不再重复询问。
3. 确认后自动拆镜，调用 `storyboard-camera` 逐小段选镜并做整体审计。分镜中的内部切镜不等于多次付费生成。
4. 列缺口表：缺什么、影响哪段、为什么需要、已有候选、建议补法与中文保存路径。
   先查现有素材；普通专业选择由助手提出方案，不要求用户提供完整专业参数。
   不擅自确定用户未授权的身份、胜负、新能力、关键剧情或付费重抽。
5. `visual-assets` 统一图片提示词；参考板交 `character-reference-board`。所有模型提示词英文，所有制作说明中文。
   用户说“中文提示词”时默认将中文需求翻译成英文交付/提交，保留中文对白和字幕需求。
6. 必要素材真实就绪、文案确认与逐段审计通过后，`autodl-aigc` 依据实时规则生成配置。
   明确生成请求直接执行当前方案一次，保存 task_id、等待、下载、实际检查；不重复询问费用，不自动重抽。

## 两条视频路由

| 输入用途 | 默认工作流 | 约束 |
|---|---|---|
| 已有或自制白模视频，保留其动作/运镜换角 | `minimax_h3_zm_titim` | 必须绑定真实 `ref_video` 和角色图，按源片长度与实际规则；简短英文映射或省略 prompt |
| 没有白模的原创、参考图连续戏份/续段 | `minimax_h3_zm_u24` | 多图/音频与英文视频提示词；不提供未声明的视频参数 |
| 非白模原视频，但要求精确继承动作/镜头 | 默认偏好仍是 u24，但当前不兼容 | 说明它不能读取参考视频；先确定可行改法或用户明确另选，不能静默把视频当作已输入 |

2026-11-09公开规则快照：titim 5–25整秒、最多9图、必需视频、prompt最多2048字符；
u24 1–15整秒、最多9图3音频、prompt最多20000字符、无 `ref_video`。
u24带 `ref_video` 的实际兼容性请求被业务拒绝为“存在未定义的参数”，未产生 task_id。
证据见 `projects/接口验证/u24白模输入-20261109/测试结论.md`；这是输入拒绝证据，不是白模生成质量测试。
以后每次以工作流实际规则复核。不得把 MiniMax 官方另一入口或 Seedance 的能力套到 AutoDL 工作流。

## 打斗补全与确认

由 `fight-scene-design` 负责武术细节，调用内部武指与3D资料；默认3D CG、动漫式紧凑攻防。
每招包含：威胁与意图 → 肢体/兵器启动与发力 → 路径 → 对手同步防守/闪避/反击 → 接触与吃痛 → 恢复衔接。
攻防重叠，回收时对方已反击，避免一方打完站正再轮到另一方；不用整段加速掩盖无力动作。
追击必须闭合距离，切镜不重置位置、速度、伤势和兵器；箭矢等未拔出时逐镜保留。
远程职业保持远端交战，写清独立投射物的飞行；每次技能有可见启动，不凭空出现特效。
近远、高低、前后景变化服务攻防，关键接触必须看得清，不能用满屏特效或乱切遮掉动作。

例如输入“A打B，15秒”：先给中文草案，说明A如何逼近出招、B如何避让/架挡和反击、
A如何接续、双方如何位移、收尾结果及待定设定。用户确认后再定稿运镜、英文提示词与素材。
这不是固定招式模板；角色身体、武器、胜负和时长决定具体编排。

## 文档、确认和审计

`剧本.md`、`视觉设定.md`、`分镜.md`、`图片提示词.md`、`视频提示词.md`拥有创作正文；
`需求.md`保存用户要求，`materials.yaml`只登记状态与实际绑定。
`分镜.md`包含每个小段的运镜审计与整体节奏结论，模板见 `templates/short-drama/运镜审计.md`。
Acheng的 `production.json` 如需编译，必须从当前已确认文档派生，记录源文件哈希；不能独立修改后反过来覆盖文档。

新作品使用 materials schema 2。`creative_confirmation`记录真实用户确认和该版剧本SHA-256；
初始为pending，不能因用户说“生成”就把尚未确认的补全内容自动标confirmed。
用户原本已给完整明确版本时，可记录该条明确指令为确认来源，无须另问一次。
剧本一旦修改，旧哈希失效；先说明变化并取得适用确认再更新记录。勿在剧本正文内写入会自我改变哈希的确认值。
程序检查状态、记录非空、版本哈希与素材；它无法证明聊天真实性或审美优劣，助手必须据实记录和实看结果。
schema 1仅兼容历史清单；新任务不能降级为1、删掉清单或直接submit绕过确认。

## Acheng的接入边界

固定源码：`.agents/resources/acheng-director`，提交 `287b5ac27c3790c665029eb4fdf94628070b2ac8`。
使用其故事、镜头、连续性、H3编译参考与132个摄影示范；不执行上游首次营销开场或重复的全套问卷。
不强制重做已合格人物板/风格母图，不套强制字数、切镜数、3秒生成碎片或其他供应商参数。
H3长格式适用于需要它的原创u24，实际字符上限优先；titim不套长模板。
原生 `compile_h3.py` 和 `audit_storyboard_quality.py` 可供离线草稿/检查，其报告不是模型能力承诺，
也不是用户确认、真实素材验收或成片验收。使用方法见 `docs/acheng-integration.md`。

没有白模时可以直接写分镜并走u24；需要更明确的空间/运镜预演时，使用 `huashu-seedance` 本地引擎。
132段视频是运镜示范，不是能自动替用户演出任意双人打斗的现成动作库；上游未附完整Blender生成器。
白模预演可验证机位与空间，复杂骨骼动作、接触和受力仍需真实动画制作与验收，不承诺自动动捕。
