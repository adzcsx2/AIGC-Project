## 采用了什么

| 上游方法 | 项目中的具体执行 |
|---|---|
| 先设计战斗，再编译提示词 | 事实/目标 → 资产与身体适配 → 攻防和状态接力 → 确认 → 摄影 → 英文执行稿 |
| 图片分别承担职责 | 身份、环境、动作起点、首尾端点分别限定控制范围；板中重复角色不增加人数 |
| 不同战斗载体有不同物理逻辑 | 刃器、长柄、钝器、徒手、远程、异能、生物和机械分别选择进攻、防守与反馈 |
| 角色选择与局势相关 | 目标、距离、风险选择、重心和累计伤势决定反击，不只写动作清单 |
| 完整的关键交换 | 攻击线与对手应对相连，接触/落空保留动量，受力位移逼出下一动作 |
| 环境后果参与战术 | 主要破坏改变路线、支撑、遮挡或优势；每次轻击不必加环境破坏 |
| 按阶段承接状态 | 15秒五阶段与短片四阶段用于容量参考；实际节拍、切镜与生成段分别决定 |
| 有因果的终结 | 在指定结局内诱出应对、利用破绽、决定性命中；落点、失去战斗能力或承接下段的状态可读 |
| 摄影与物理声音围绕动作 | 每镜主任务/主运镜明确，接触与核心身体入画，声音对应真实材料与动作 |
| 同一时间线编译 | 中文导演说明和英文正文逐项核对动作、镜头切点、伤势、速度强调、声音和终局 |

## 对冲突作出的适配

| 上游约定或冲突 | 本项目决定 |
|---|---|
| 缺省15秒、16:9、无对白；固定中文七段 | 保留本场画幅/声音与用户时长，依据容量和真实接口灵活安排；中文用于导演稿，模型提示词沿用项目语言规则 |
| 约15秒强制五段与完整胜负 | 五阶段只是参考，中间段不擅加终结，未指定胜负不判死；死亡过程时间不足先减中段动作 |
| 开场至少三条攻击线 | 不设硬性招数配额，身体结构、屏幕时长、有效变化和接触可读性优先 |
| “不停/连打”模式限制角色暂停或慢动作 | 普通连续打斗保留用户要求的快速动作＋命中时停；本次明确禁用时停/慢动作才采用严格全速 |
| 双方能力默认近中距离 | 沿用当前角色与明确战斗距离，远程对决不被强拉到近战；魔法可以夸张但仍须有源、可读 |
| 缺对手时可自动加轮廓对手 | 只在草案说明缺口/建议，未经确认不新增角色或标记素材就绪 |
| 阶段至少继承四项状态 | 核对所有与当前镜头有关的状态；不能漏掉断臂、伤势、装备、动量或余波 |
| 每份提示词前缀BUNNY | 属于上游特定约定，本项目不自动添加，也不视为通用模型触发词 |
| 外部依赖h3-prompt-writing | 未安装，不假装可用、不为本次整合引入新依赖；继续使用现有摄影资料与autodl校验 |
| 英文仅限Ref2VA六段 | 作为适用入口的表达参考；白模titim和真正首尾帧等用途按真实接口组织，不套通用模板 |
| SKILL允许英文增切镜，但双格式合同要求镜头严格一致 | 采用严格同版对照；编译不得加减镜头，实质变更回到导演/分镜阶段 |
| 上游要求每份最终稿双语同交 | 保留中文创作说明与英文模型正文的现有分工，不强增第二份可提交中文提示词 |

上游没有渲染器或AutoDL接入，其文本方法不构成对实际生成质量、时停帧数、首尾帧或参考视频输入能力的保证。

## 场景核对与验证范围

以下是对最终指令作的人工情境核对，不是独立模型测试，也没有调用生成API：

| 情境 | 核对后的行为 |
|---|---|
| “按这两张图写15秒高密度打斗” | fight读取合同，按真实装备/身体编排；细节不足先交中文草案，不抢先生成 |
| 重要命中要快动作＋时停，全程连打 | 连打不关闭时停；关键接触强调后沿余势回速，不恢复站桩 |
| 本次明确禁用慢动作和时停 | 覆盖默认时停偏好，改用全速接触与密度/位移变化 |
| 8秒片段未指定胜负 | 简化阶段并保留可读的进行中状态，不硬塞15秒终结或擅加死亡 |
| 30秒双怪物，前半断臂、后半焚杀 | 断臂逐段继承，后段不用缺肢施法；终局留时间，片段数量另按分段规则审计 |
| 两个角色已指定远程法术对轰 | 保持远距离和真实投射路径，夸张特效不能掩盖启动/应对 |
| 无飞行设定的沉重生物 | 用实际支撑与惯性行动，不因阶段需要换高度而补飞行或轻功 |
| 一名徒手对手遇到锋刃 | 使用避线/控臂或非刃部应对，无依据不裸手硬接，不临时生出兵器 |
| 只有一张单人图且对手未定 | 标出缺口或草案建议，不在生产中直接加入轮廓对手 |
| 无法破坏的空旷场景 | 用已有边界/距离/支撑关系推进，不为配额新增墙体或坍塌 |
| 已确认镜头编译英文 | 切点、顺序、动作和结果保持同一版；不因英文格式增镜或补新招 |
| 已确认首尾衔接图 | 检查状态可达与边界约束，不能把身份参考或格式标签冒充接口字段 |
| 白模原片只换角色 | 走retargeting与专用接口，保留源片动作/摄影，不套原创高密度重编 |
| 用户只要求融合技能 | 更新本地规则与资料，不触发图片、视频或付费重抽 |
