# 简单几何白模与摄影机规则维护

依据：用户2026-11-10在《巨树下的拥抱》三路线对比后明确偏好圆柱方案，要求以后白模只做简单几何，可用不同纯色表示人或物，让视频模型通过提示词完成更多细节，并要求白模考虑镜头语言和实际摄影机控制。

本次交付为规则/技能维护，不制作新白模、不重做已提交视频，不将路线偏好登记为体型和爬树效果已接受。该片已有反馈“幼龙变大、没有爬树”仍保留。

## 规则与职责

- `AGENTS.md`登记硬约束；`docs/工作流/白模制作与验收.md`唯一维护具体制作分工、摄影机控制数据及检查边界。
- `docs/skill-routing.md`保持现有职责：`storyboard-camera`设计机位、角度、成像参数、目标、路径/速度和切点；两个Blender技能用简单几何与实际Camera实现，不增设重复摄影技能。
- 同步两个Blender技能、摄影技能、替换技能及相关UI/交接参考；白模计划、运镜审计和总审计模板包含检查入口。
- 移除当前共享流程中“先粗模再制作关节”“Rigify作为白模起点”“必须制作完整非人轮廓”等冲突默认；历史任务、上游原文和能力验证保留并注明适用边界。

## 具体检查边界

1. 简单造型不省略主体数量/比例、路径/高度、接近/接触/分离和必要道具轨迹。爬树须真的贴树升降，圆柱平移只代表路径，不代表自然步态已通过。
2. 稳定纯色/灰度是身份标签，不是最终材质；明确主体→尺寸→颜色→角色参考映射，跨镜不交换身份。相对尺度写入英文提示词并按真实输入审计，不照搬本片厘米数到所有作品。
3. 模型补全自然步态、肢体/翅膀、表情、材质与微观接触反馈；提示词不能同时要求照搬刚性代理动作。成片效果仍需实际检查，规则不能保证模型服从。
4. 相机方案必须对应工程里的实际对象、参数、动画和切点；静止镜头有叙事理由，移动镜头检查路径、速度、朝向、遮挡和覆盖。不把YAML中的`camera_motion`当控制器。
5. 当前通用导出工具的审片版为语义色、送模版为灰度；本次没有增加彩色送模API或参数。允许采用纯色方案，但真正提交前必须使用实际支持的无标注导出实现并保留检查证据，不能拿带字审片版冒充。

已完成：4个修改技能通过官方`quick_validate.py`；UI描述长度、显式技能名和自动选用策略有效；18份相关Markdown的本地链接全部存在；白模计划与调用模板YAML可解析；修改技能及其登记参考的SHA-256匹配，安装清单的活动入口与实际目录一致。精细建模与简单占位的冲突默认已定向修正。
