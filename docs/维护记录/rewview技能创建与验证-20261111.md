- 同步 [路由](../skill-routing.md)、[导航](../CODEX-NAVIGATION-GUIDE.md)、[README](../../README.md)、[电影级技能交接说明](../../.agents/skills/cinematic-script-audit/SKILL.md) 和 [安装登记](../installed-skills.yaml)。电影级基准与生成提醒前总审计职责未替换，不让两个入口相互递归启动。

## 场景推演

以下为维护者按技能逐案进行的人工推演，示例均为测试用虚构输入，未修改任何生产稿、调用生成模型或提交付费任务。表内结论是对技能决策边界的检查，不是独立模型行为测试或成片验收。

| 输入情境 | 推演中得到的具体判断/处理 | 结果 |
|---|---|---|
| 普通活动文案：“11月12日19:00线上开始”，同轮明确事实为20:00，未提供入场链接 | 时间是有依据的必修项；可改为“线上活动将于11月12日20:00开始”。入场链接列遗漏/待提供，不编链接，不要求风格、三视图或白模；必要发布信息未齐不称发布稿全部通过 | 范围与事实边界成立 |
| 只审不改：分镜写上身挥击，却只给腿部特写 | 指出攻击启动、路径与接触未被构图覆盖，引用camera标准；建议在主攻击前回到覆盖机位。原稿状态仍为需修正，不能把建议写成已修复或改源文件 | 只审模式成立 |
| 固定半身镜头、台词逐字保留，只优化人物反应 | 可以补原刺激后的目光、呼吸与可见肩颈反应，并核对听者；不能靠改成面部微距或增加对白来优化。用户固定镜头要求作为镜头变化例外 | 保留项与适用例外成立 |
| 日常舔饮只写“舌头动”，没有对象响应 | 定位接触、液体转移与结果遗漏；局部补法应覆盖触液、少量液体附着随回舌入口和液面变化，下一镜保留合理湿痕/液量。只说明文字设计，不能声称输出物理已通过 | 物理反馈与后果复核成立 |
| 两个独立视频请求，第二段漏掉已定风格和生成期禁音乐约束 | 不能用首段已写或中文说明已写代替第二段实际英文正文；第二段提示词需修正，再对中文方案和实际配置复核 | 逐请求覆盖成立 |
| 提示词需要对照人物参考，但文件不可读，同时句内还有错手矛盾 | 可先修不依赖图片的文本矛盾；身份/服装/真实绑定保持待核实。交有标记的草稿，不把“参考一致”当已见图证据，不自动生图 | 独立推进与证据边界成立 |
| 只改镜头2，修正站位后发现镜头3的承接需要变化 | 读取镜头3检查影响，只修授权的镜头2；标出镜头3的依赖冲突和候选补法，不扩大改稿，也不称全段连续性通过 | 局部范围成立 |
| 已确认结局为逃脱，优化时认为角色死亡更有冲击力 | 该建议属于改变已确认结局，不能直接纳入定稿；保留逃脱，另列候选及代价，原确认记录和哈希不伪造更新 | 实质变更边界成立 |
| 根规则有新三视图标准与新默认模型，旧技能残留旧版式/路由 | 按真实更新依据与范围判断本轮标准；新版方案使用当前要求，实际模型字段仍待真实契约；历史任务沿原记录，不修改规则来放行或自动重提 | 规则冲突与历史边界成立 |
| 用户只要剧本复审，尚未制作角色板、白模和音色 | 对现有文字完成叙事、表演和因果检查；制作资产列后续依赖，不因此拒绝剧本交付。若改为要求可提交方案，则缺关键资产会影响就绪结论 | 阶段适用性成立 |
| 第二轮修改补了接触却挤掉反应时间 | 第二轮不能直接结束；重新检查时间与表演覆盖，实际修正后再复核。可选润色未采用不阻断必需项通过 | 闭环与停止条件成立 |
| 仅要求“生成前检查”，或显式用rewview检查整套生成方案 | 前者直接cinematic；后者由rewview整合并履行cinematic总审计，共享当前版本证据，不递归重启，不以局部通过宣称可生成 | 入口交接成立 |
