# AI视频制作能力对照与取舍

依据2026-11-10读取的官方资料及本机代码审计。本表是针对单人+Codex制作方式的判断，不是市场份额排行。

| 参考 | 值得保留的能力 | 本项目处理 |
|---|---|---|
| ComfyUI：可复用工作流、API、输入参数与执行 | 可复现输入、真实参数、任务恢复 | 沿用 Python+YAML 客户端、catalog、materials 和 task_id；不建立第二个节点工作台 |
| Kitsu：动画/VFX生产协作 | 项目、素材、制作记录有明确归属 | project.yaml入口加作品内分层目录，素材状态只在materials维护 |
| Frame.io：版本比较、时间码/区间反馈 | 意见能定位到具体版本与时刻 | 轻量本地网页、版本切换、区间循环、精确静帧、哈希绑定记录；本轮未实现双播放器帧同步对比 |
| OpenTimelineIO：剪辑时间线交换 | 原片入出点、时间基、媒体引用分开 | 剪辑记录保存源区间和全片接缝，配乐绑定剪辑哈希；目前不宣称支持OTIO导入导出 |

来源：[ComfyUI官方仓库](https://github.com/Comfy-Org/ComfyUI)、[Kitsu官方仓库](https://github.com/cgwire/kitsu)、[Frame.io版本比较](https://help.frame.io/en/articles/9952618-comparison-viewer)、[Frame.io时间码意见](https://help.frame.io/en/articles/9105251-commenting-on-your-media)、[OpenTimelineIO官方仓库](https://github.com/AcademySoftwareFoundation/OpenTimelineIO)。

本轮优先补齐：作品内素材/输出归一、按内容去重、机器可读入口、媒体处理共用程序、版本化审片证据、后期音乐/留白时间线、独立水印发布版。这些解决已有项目的实际断点。

仍需如实区分的能力：专用AI音乐模型未接入；旧片混合对白+BGM的可靠分离未实现；画面语义好坏和实际听音不能由解码/ASR代替；双播放器精确同步、编辑器互通、多人权限审批均不在这次轻量工具范围。后续有实际需要时再加。

审片选择网页加Python后端：网页便于直接播放与记录，Python统一探测、精确解码和导出；无须安装桌面GUI或自动控制本机播放器。大文件直接Range串流，静帧按需缓存，避免每次拷贝整片和逐秒启动大量进程。
