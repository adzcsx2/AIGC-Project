# 自然语言需求与技能路由

共享资产职责：配置/代码维护是开发工作；跨作品查找、造型与版本选择按 [共享资产流程](工作流/asset-library.md)。visual-assets/character-reference-board维护所产素材的身份与造型引用，workflow持有作品使用选择和确认，autodl核对导入后的本地文件/哈希/实际槽位。声音与配乐继续归各自既有流程，不新增竞争的状态或制作入口。

这是项目技能选择与交接的唯一维护表。根目录AGENTS先应用本表，再按需读选中的SKILL.md；不用用户输入 `$`，不把所有技能全读一遍。明确点名的技能要使用，同时服从本次任务范围与用户最新要求；已有工具/项目规则仍适用。

## 先确定任务，不按单个关键词触发

开始时结合当前消息和同一任务的已确认上下文判断：

1. **交付物**：解释/分析、文案、演技、分镜/提示词、图片/参考板/衔接图、白模预演、视频、已有任务结果、合成、规则/代码修改。
2. **素材用途**：身份参考、场景参考、学习镜头、精确继承动作、只做测量。提供视频不等于要复刻；提到白模不等于要制作白模。
3. **当前状态**：已有剧本/选图/边界图是否确认，是否已有task_id或替换段，刚才等待的是哪一项用户决定。先查当前作品文件与记录，不能每次重走流程。
4. **本轮范围**：只问是否支持、只写提示词、实际生成、重做指定段、沿既有授权继续。选中生成技能不自动产生生成授权；已明确授权的下一必要步骤也不重复确认。

选一个对最终交付负责的主技能，只添加有具体缺口的协作技能；协作数量由需求决定。**凡写、补、改视频剧本，必须先参考 `cinematic-script-audit` 及其检查清单，再使用动作/运镜等专业技能。** 单项工作仍由对应技能交付，跨阶段新作品或多片段制作才由总导演调度。按依赖顺序交接，不让多个技能各写一套剧本。回复开头用一句普通中文说明本次分工即可，不要求用户选择技能，不堆长路由清单。

默认视频规格为16:9横屏，生成和剪辑默认24fps，最终成片自动补到60fps，不考虑平台UI安全区域；用户明确要求和当前作品已确认规格优先，动作构图余量仍须检查。生成决策流程固定为：最终方案→`cinematic-script-audit`总审计并修正→展示结论并提醒/询问是否生成→用户确认后提交。**不能在用户说“确定生成”之后才开始总审计。** 若审图确认承接直接生成，总审计提前到最终审图材料交付前；已有授权不重复征求费用同意。纯查询、恢复、下载、仅合成、补帧不触发此创作流程。

## 项目技能的边界

新视频统一u30多图生成，不制作/提交白模，取代旧默认先白模及titim分流。实际素材与提示词执行 [u30多图规则](工作流/director-workflow.md#u30多图身份身高与完整同框规则)。先review提示词/素材方案、修正后生图，再核对返回图/实际配置与电影级总审计后按已有授权生成；历史task_id仍恢复原入口。

技能路径均为 `.agents/skills/<技能名>/SKILL.md`。维护规则/技能时使用可用的 `skill-creator`，不进入媒体制作；修客户端/测试属于开发工作，按代码范围执行，不加载与问题无关的导演资料。用户明确调用其他技能或插件时按其任务使用，不以项目路由屏蔽明确请求。

`high-density-fight-prompt`已作为内部方法融入fight与camera；用户提到这个项目或它的15秒合同，读取fight中的项目适配合同。上游原文位于 `.agents/resources/high-density-fight-prompt/` 供追溯，不是新增可调用入口，不绕过既有确认、接口与时停规则。

`VLM-Generation-Harness`的方法融入现有两个Blender技能，共享执行依据为 [白模制作与验收](工作流/白模制作与验收.md)，按症状读取 [故障排查](工作流/白模故障排查.md)。不新增竞争入口；`.agents/resources/vlm-generation-harness/`只保存固定版本来源，实际工具是 `tools/视频工具/白模.py`。有合格白模只换角仍直接retargeting。

## 组合与交接

**文案、设计与媒体专项复审**：`review`持有本次固定范围、验收对应、五轮记录、修订及最终结论；完整复审与放行条件见[review入口](../.agents/skills/review/SKILL.md#五轮循环放行与停止条件)，不以局部复查替代。显式调用review时由其统筹，动作设计的速度独立必查，已有白模/视频按当前问题取证，区分输入已有缺陷、模型新增偏差和后处理变时；媒体专项方法在review参考中，物理/速度规则仍只由白模共享规范等专业文档维护。涉及生成决策则应用cinematic当前版本总审计，仅“生成前检查”仍直接cinematic；电影级基准/总审计及workflow状态职责不变。复用同版本规则和原始证据时重新核对适用性，不沿用旧通过结论、不递归重启两套循环，也不自动增加普通制作的全量逐段创作验收。一般文案不套影视规格，缺媒体不阻断可独立判断的纯文本项，但不能标对应实测通过；需改确认内容交候选，缺证据标影响。纯文案复审不自动扩为规则维护或修片，已有媒体专项不等于用户整片认可，审计均不授权收费重抽。

**新角色视觉前置**：workflow/visual/retargeting识别新人物、动物及其他生物→board从已确认设定或原图制作固定三视图→按既有授权验收归档→visual以三视图制作含角色的场景/镜头图→autodl核实每个实际请求的三视图身份输入。详细契约唯一见 [人物流程](工作流/character-voice.md#新角色三视图前置与api绑定)；无身份依赖的白模/环境工作可继续，不用场景图替代三视图，不因API不兼容而静默跳过。

- **新故事到成片**：workflow持有状态；先用cinematic-script-audit建立剧本基准→需要时fight补动作并取得确认→camera分段/摄影→acting补可见反应→visual或board补对应图片，autodl提前核实真实参数→cinematic-script-audit总审计并修正→展示结论/生成提醒→用户决定后autodl执行。已存在且合格的步骤跳过，当前版本总审计未做不能跳过；已有生成授权不重复确认，实质创作变更依原规则处理。
- **多片段**：先应用电影级剧本基准；workflow＋camera审计模型段内切镜、首尾图分段或混合；visual制作按切镜设计所需的前出/后入图及必要端点。cinematic-script-audit覆盖全部计划片段，在交付最终审图/生成决策材料前完成总审计，用户接受该方案和图片后autodl直接提交。技术检查后由workflow逐一验收全部N−1个接口、安排本地合成与实查，补帧后再查最终接口；整体创作交用户审视频。规则见 `工作流/multi-segment-video.md`。
- **原片复刻**：retargeting主导，必要的breakdown只测本次需保留的动作/接触；board仅补身份与身体结构缺口，遵守固定三视图，不添加运动格；动作由引导及英文视频正文承载，autodl核实专用接口。不得夹入原创fight重编或新增camera切镜。
- **白模制作与替换**：原创分镜→blender-video-original；参考视频重建→blender-video-recreate。每次制作承接storyboard-camera的摄影意图、机位/角度/焦距、跟随目标、路径/速度和切点（已定稿复用，不为复刻新增镜头），Blender仅以圆柱等简单几何落实比例、空间轨迹/接触和实际摄影机，可用稳定纯色区分主体。交真实工程/预览及主体映射，retargeting承接角色/场景图与英文提示词，让模型完成自然步态、肢体、表情和材质；autodl核实真实输入。分工细节与能力边界统一见 [白模制作与验收](工作流/白模制作与验收.md)。已有合格引导直接复用；后续生成仅在用户已要求时执行。
- **反馈或局部修正**：先定位是动作、摄影、表演、身份/图、接口还是纯技术问题；可组合对应技能。例如“打击软、镜头还裁身体”由fight＋camera协作，表情、情感或肢体反应需补时增加acting。不为“优化”自动提交收费重抽。
- **只合成已有码流**：按已有片段映射与用户认可版本，由workflow默认采用 `工作流/multi-segment-video.md` 的已审切镜/转场选切点、删多余等待；旧连续场景才按版本04匹配运动、按需局部压短收势/启动及重复准备，音画同步，自动调用补帧到60fps并完成全部N−1个接缝验收。无需autodl提交新任务、无需默认breakdown整片审片。用户认可替换段后自动重合成，并按新版时间线复查接口；已有流畅接口不强制变速。

**最终视频交付**：workflow、autodl或retargeting把完成剪辑和音轨的最终文件交 `补帧`，单段、多段及替换后重合成都默认60fps，无需用户点名。已达60fps核验复用，用户明确另定规格或不补帧时遵从；中间预演/白模引导、仅查询/下载原始结果和规则维护不触发。

**审片通道**：以上入口以及breakdown遵循 `AGENTS.md` 和 `工作流/multi-segment-video.md`「网页审片与辅助检查」，默认网页播放，禁止桌面 Computer Use；测量/抽帧/ASR是辅助，不改变动态与听音证据门槛。

**人物音色交接**：workflow持有人物YAML及待试听队列，visual/角色板维护同一身份的图片引用，camera只标剧本需要说话的人物与剧情称呼，cinematic审声音绑定/依赖，autodl核实真实接口并执行已授权声音任务。详细规则唯一见 `docs/工作流/character-voice.md`；仅剧本需要说话时触发配声，无台词/非语言声不要求配置。需要说话但未配声先做独立工作，最后集中试听，确认后接续。接口审计/规则维护不启动收费试听。

**声音交接**：camera区分生成期对白与后期音乐意图，cinematic审无BGM约束及有乐/无乐理由，autodl核实真实输入和音乐生成能力；workflow在剪辑后按全片时间校准cue、安排音乐与混音，再交补帧。`docs/工作流/music-postproduction.md`为唯一详细流程，配乐计划引用现有materials的音频资产；音乐制作/插入小工具的规划不代表已部署。已60fps且仅改音轨时复用视频，不重复插帧。

每次交接携带：当前作品/片段ID、用户目标和已确认版本、输入文件及状态、必须保持的事实、要补的具体缺口、下一份交付物；新生成决策还须携带当前版本的电影级总审计结论。沿用现有剧本/分镜/提示词/清单/片段映射，不为路由新建一套竞争生产状态。技能规则说明要做什么，不代表执行或验收已经完成。

## “继续”“这张可以”依赖当前节点

| 当前上下文 | 下一步 |
|---|---|
| 刚交补全动作草案，用户说“好” | 确认该版草案；继续已要求的分镜/制作准备，不把只写提示词的原任务升级为生成 |
| 已要求完整视频，已展示该版总审计结论且衔接图待审，用户说“都可以” | 记录选图，核对已审版本与实际参数后提交计划内片段；不再问是否继续或是否付费。若实际方案变动使审计失效，先修正依赖并展示更新结论，不能借此节点绕过总审计 |
| 用户只要参考板，确认了板 | 归档并完成本任务；不擅自启动视频 |
| 视频已提交，有task_id，用户说“继续/好了没” | autodl查询/恢复/下载同一任务，不重新提交 |
| 用户认可指定段替换版 | 更新版本映射并自动本地重合成，不重抽其他段 |
| 只说“效果不满意”，没有要求重生成 | 登记并按需要提出具体修法；不把反馈当成自动付费重抽授权 |

“参考这个视频”仍有实质歧义时，先查看上下文和可用素材；只有保留原动作还是借风格会改变交付且仍无法判断，才集中问这一项。普通专业选择自己完成，不把整套技术问卷交回用户。

## 规则冲突与能力缺口

最新明确用户要求优先；同一层级先看作用范围，再看更新时间。特定作品的授权/姿态比例不能推广到所有任务。项目入口以 `.agents/skills/` 中实际存在的SKILL.md为准，增减时同步本表与安装清单；`.agents/resources/`是按需资料，`docs/archive/`是历史，均不当新技能或最新执行指令。

职责表只决定谁执行，不能扩大授权：明确参考板生成请求或已授权制作中的新角色前置，使用`character-reference-board`对应生图授权，无需另点名三视图；只写剧本/提示词、查API、恢复任务或维护规则仍不生成。来源实例、已提交YAML和演示模板中的时长/比例/帧率不自动成为当前作品缺省。普通缺省与未给预算的处理统一见根规则“授权、确认与缺省”。

技能匹配和API选择是两次决定。真正首尾帧、参考视频等能力必须由autodl核对真实字段；不因选到skill就声称已部署接口。找不到合适职责时说明具体缺口，并完成可做部分；不要借名字相近的技能虚构能力，也不为一次一般问题扩建技能。

分镜时长由autodl-aigc先提供所选API当次范围、步长/枚举和参考视频长度关系，storyboard-camera据剧情容量定秒数，白模技能按已审秒数落实；cinematic-script-audit复核方案与实际请求一致。无通用15秒或25秒上限，执行细节只见 [按实际API规划时长](工作流/multi-segment-video.md#按实际api规划时长用户2026-11-11要求)。

路由是给Codex执行的指令，不是代码层的语义分类器或百分百命中保证。验证分为技能元数据/链接检查与有上下文的场景推演，不能把文本检查称为真实生成效果测试。
