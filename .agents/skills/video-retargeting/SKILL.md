# 原视频驱动角色替换

新增/重做视频内容按 [默认先做白模](../../../docs/工作流/白模制作与验收.md#默认先做白模) 先完成简单预演或核对复用；真实原片/白模参考的用途与最终实际输入分别记录，用户明确源片保留要求继续遵守。纯恢复、下载和现有文件处理不倒补白模。

人物按 `docs/工作流/character-voice.md` 独立建档；仅剧本需要人物说话时配置音色，无台词/非语言声不触发。明确保留源声时记录源片声音来源，不从“已有音轨”推定用户已选定角色声线。titim当前无独立声音参考槽，不伪造字段或为建档重做原片；要换配音时审计实际路线，继续无关工作，最后集中试听。

此技能衔接实际安装的源技能与本项目 Python 客户端。先读 `docs/工作流/director-workflow.md` 的最新路由，再读根目录 `AGENTS.md` 和
`docs/工作流/video-retargeting.md`。路径默认相对项目根目录。

## 白模输入的完整执行路线

白模可来自其他视频工具、用户已有素材或本机Blender；已有合格视频直接使用，不因接入Blender技能强制重建。
需要制作/修改三维白模时，原创交`blender-video-original`，源片重建交`blender-video-recreate`；工程与视频分别记录。

新做或修改白模按 [简单占位规范](../../../docs/工作流/白模制作与验收.md) 只用圆柱等基本体，可用稳定纯色区分主体；白模控制比例、路径/高度、接触位置和摄影，自然身体表演交参考图与英文提示词。既有原片的精确运动继承与圆柱代理的空间继承分别处理，不把圆柱平移写成必须逐帧复制的真实步态，也不套外部技能的人形精模建议覆盖本轮规则。已有引导仅使用时不自动重建。

视频＋人物/场景图的白模复刻，先读已安装的
[白模视频技能](C:/Users/long/.codex/skills/clay-video-retargeting/SKILL.md)，
按事件时序、身体结构冲突、必要引导修正、素材绑定、一次生成、实际验收推进。
用户已允许为目标效果适当修改白模副本；保留源片方向、关键镜头和原声，避免仅改提示词而复用错误引导。
缺身份板时用 [人物三视图](../character-reference-board/SKILL.md)，仅正面特写、正面全身无头、背面全身；非步行角色也不自动加运动格，运动方式由引导和英文视频正文承载。
原片复刻不套普通原创视频的15秒或新多机位模板；案例未通过的尾尖退出速度不能记成完美复刻。

## 先判断输入与目的

- 视频默认优先u30，仍先完成白模；u30当前不读取参考视频。若必须继承白模/原片的指定运动与机位，先说明缺口及视频兼容候选，由用户明确选择；不得删视频降级或伪造绑定。简单占位只约束空间/摄影，身体细节由提示词补全。用途与兼容路线以导演流程为准。
- 只想让角色模仿动作：说明可选专用入口的能力差异；只有用户明确另选后才用Wan等，不承诺背景逐像素不变。
- 想自己设计空间与运镜：新任务由`blender-video-original`优先调用本机`D:\blender-5.3.0\blender.exe`；参考视频需三维重建/修正用`blender-video-recreate`。
  `huashu-seedance`只保留明确指定的旧scene.json/照片拟合流程；这些技能均不自带任意视频自动动捕。
- 想把任意原视频转成白模外观视频，或明确提取深度/姿态/遮罩再重绘：读取上述文档的能力边界。
  当前没有部署深度推理模型、原视频到3D动捕或 VACE 控制执行端，不能伪造已可运行。
  不把灰度滤镜当深度、不把抽帧当骨架，不向 AutoDL 编造 depth/pose/mask 输入参数。

## 查看并准备原片

原片归 `projects/<中文作品名>/02-素材/参考原片/`，静音派生片及换角输出归 `04-输出/`，检查帧归 `05-检查与验收/`；目录和文件名统一用中文，
例如 `原片.mp4`、`引导视频-静音.mp4`、`镜头01-双人对峙.png`；同改清单和 YAML 引用。

1. 用 `autodl media inspect 原片.mp4` 读取时长、画幅和音轨。
   需要测切点和生成代表帧时，使用 `short-drama-breakdown` 的 `breakdown_tool.py measure`；
   只做本次需要的观看与镜头测量，不自动进行竞品研究或付费对照生成。
2. 先实际查看代表帧，确认出镜人数、目标角色、遮挡、角色换位、武器接触和切镜。
   保留原片及原音轨；用户明确要求去音轨且工作流允许时才使用无音轨副本命令：
   `autodl media prepare 原片.mp4 --output projects/作品名/04-输出/处理过程/引导视频-静音.mp4`；
   截片再加 `--start 秒数 --duration 秒数`。该工具不联网、不上传、不扩时、不覆盖已有文件。
   仅去音轨时对 H.264/HEVC 复制视频码流；截片会重新编码以准确对齐起点。
3. H3 原片较短时不默认用更长 duration：上游说明尾部可能自由发挥。
   当前替换规则为 5–25 整秒，以实时规则为准；不足 5 秒或非整数时长须说明取舍，
   不偷偷补帧、循环、变速或延长剧情。长视频按镜头处理，切点/遮挡处检查换人稳定性。
4. 原声默认保留，不因“只参考动作”自行静音。Wan/VHS已发生无音轨输入提取音频失败：
   用户明确要求静音且入口需要音轨时保留全静音AAC副本，检查峰值为0及帧数/时长。
   最终是否保留原声需实际检查；必要时本地合回原轨，不用`-shortest`截掉生成画面。

## 角色和输入绑定

- 新增/替换角色包括动物，先按 [三视图前置与API绑定](../../../docs/工作流/character-voice.md#新角色三视图前置与api绑定) 生成并验收独立三视图，再将其作为实际API身份输入；原片角色或场景里的临时外观不能替代新角色三视图。已有同身份合格板复用，接口不兼容先解决方案，不静默只传场景图。
- 体量关键时先应用 [导演流程「主体与物体的尺寸约束」](../../../docs/工作流/director-workflow.md#主体与物体的尺寸约束)，让已确认大小、实际白模、参考用途和英文相对尺度一致；分开身体尺寸与所在高度，遮挡重现保持实体大小，不能只换形容词而保留冲突引导。
- 实际查看自己的角色图，核对全身比例、脸、服装、身体结构、武器、画风与目标镜头是否可见。
  身份与身体结构缺口使用 `character-reference-board` 的固定三视图；按已授权工具生成或交付用户指定的MJ提示词，
  不把“等用户补图”当作已有生成授权下的固定停点。
- 默认优先u30；其不能满足实际视频驱动时先说明并由用户选择。旧titi/titim示例仅能力说明与历史，不作自动路由。
- 用户选用 `minimax_h3_zm_titim` 时，真实输入为 `ref_image_0..8` + `ref_video`。
  明确图1换哪个原片主体；位置或特征以所查看的原片为准，不靠文件名猜。
  `video_subject_to_replace` 默认 person，仅按平台支持填英文检测类别；
  圆柱引导须按真实可见对象核实检测类别，不能机械沿用person；颜色和角色映射写入prompt，不能假设颜色就是API分割ID。
  上游对“一种类别”和文末“逗号多个类别”的说明有冲突，稳妥使用一种明确类别。
- 用户明确另选Wan动作迁移时使用 `wan2.2animate-v4-motion_retargeting`，输入 `ref_image` + `ref_video`。
  该工作流不接受 prompt/duration/depth 等未声明字段，按视频计费，当前客户端不能可靠估价。
- **上述 H3 替换专用工作流使用简短英文主体映射，按本片需要补项目风格、运动例外、接触因果和镜头约束。** 按导演流程「项目风格与防漂移」读取本片style及已认可图，区分身份/风格与引导动作；不能省略必要风格要求或把额外角色槽冒充独立style槽。没有prompt字段的入口用真实参考承载并记录限制，不添加假字段。
  不套 `short-drama-video-prompts` 的普通 H3 六段式，平台明确说明可能影响替换效果。
  不把白模技能的 Seedance `@白模1` 标记塞给 H3。

## 检查、预算与生成

在交付最终换角方案并提醒/询问是否生成之前，使用 [电影级总审计](../cinematic-script-audit/SKILL.md) 检查实际源片、身份映射、身体适配、输入与保留项，并先展示结论；不重写原剧本或新增运镜。当前请求已明确授权且无实质变更时，完成方案准备与审计后按既有授权执行；纯静音/截片/查询下载不触发新视频总审计。

读取 `autodl-aigc`，查询实际工作流参数。示例配置在 `examples/character-replacement.yaml`
和 `examples/multi-character-replacement.yaml`。短剧中的换人镜头沿用 `materials_manifest/shot_id`，
同时登记 `kind: video` 的实际引导片和角色图，reference_bindings 必须包括每个实际视频/图像字段。
独立视频换人不必伪造一套剧本，但仍先看图看视频并执行离线 validate。

用户明确请求当前生成即按根目录最新直接执行规则 run，不重复查费或询问费用确认；
未指定预算时省略预算字段，有明确上限则遵守。仅安装技能或审计不授权新视频。
保存 task_id 并恢复轮询，未知提交结果不重试。
验收看身份、角色映射、动作时序、接触、手和武器、遮挡、场景、画幅、切点、音轨，不能只看首帧。

## 最终交付帧率

最终成片默认60fps：完成结果检查与原声处理后自动交 `补帧`，用户无需另点名；单段及重做后成片均适用，已是60fps核验复用。补帧保留已确认的动作时序、镜头、时长和音轨，不借此重编原片或改变播放速度。用户明确另定规格或不补帧时遵从；原始输出、白模引导与仅下载原片不自动处理。

## 白模与深度扩展

`huashu-seedance` 的引擎、参考和模板已安装完整。先 probe，再 build；
渲染需要 `hyperframes@0.7.107` 和其浏览器运行时，照片叠网格还需要 opencv-python。
只在实际需要时准备这些运行依赖，不擅自把 MiniMax 路线改成 Seedance 付费服务。
不把作者小样本的精确切点、数量、分辨率等经验当成本项目 API 规则或必然效果。
深度/姿态控制需要另有真实执行端和工作流输入契约，当前仅记录官方候选与接入缺口。
