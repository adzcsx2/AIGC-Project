# 补帧

**项目最终成片默认60fps，生成和剪辑默认24fps。** 剪辑、拼接和音轨完成后自动调用本技能处理完整成片，用户无需再输入 `$补帧`；同一作品替换后重合成也执行，无需重复确认。用户明确要求其他帧率或不补帧时遵从。
总导演或生成/动作迁移入口交接目标规格、最终文件与片段映射；单段成片也适用。
用户给文件名、路径或明确指向某个视频要求补帧时，也直接完成本地处理、检查并交付。默认60fps；
用户指定其他目标帧率时遵从。保留原片、播放速度、画幅、分辨率和原音轨，不需要 AutoDL API。
创建或修改本技能时的示例文件名不是处理视频的指令。
纯规则审计、中间预演/白模引导、原始任务归档与只下载原始结果不自动调用成品处理。

## 确定视频

优先使用当前聊天已经明确的完整路径、刚下载/合成的视频，或用户选定的版本。
只有文件名或描述时，先在当前目录及 `E:\AutoDL` 的 `projects/` 下的作品素材中查找：

```powershell
& 'E:\AutoDL\.venv\Scripts\python.exe' 'E:\AutoDL\tools\视频工具\补帧.py' '双人对决' --find
```

可重复传 `--search-root '目录'` 扩展到用户给定的其他目录。`--find` 只查找，不处理。
不要将已有补帧版当原片；同名、不同版本或描述匹配多个视频时，列出具体候选让用户选择，
不能自行猜一个版本。明确路径可直接处理，不再要求用户复制文件或重复确认。

## 执行

生成新的局部补接片与本技能的帧率插帧分开。补接片不带入新生成声音，原底轨按上游时间线保留/同步；本技能不能补回停住后缺失的动作或替代跨段切镜设计，详见multi-segment-video.md。

若当前任务是已知的多片段制作/接缝修复，先由 `short-drama-workflow` 按
`docs/工作流/multi-segment-video.md` 完成全部N−1个接口的原生帧率剪辑验收，再把修好的合成版输入本技能。
RIFE不能修复前段尾部与后段开头累积的等待，不以60fps替代运动检查，不从旧补帧版再次补帧。
单条现成视频只要求补帧时仍按原用途执行，不因没有片段映射强制重启导演流程或整片创作审计。
多片段上游按该文档已审的切镜/转场选切点并同步声音；旧片或用户明确连续例外才采用「既有连续镜头剪辑：版本04方法」匹配运动与局部节奏。最终检查明确硬切是否被跨界插值混合，场景检测开启不等于切点已受保护；不把光学转场标签或帧率达标当成流畅结论。
本技能保留的是**这份已剪辑输入**的时长和速度，不撤销其局部变时，也不在补帧阶段再次改动作节奏。

```powershell
& 'E:\AutoDL\.venv\Scripts\python.exe' 'E:\AutoDL\tools\视频工具\补帧.py' 'E:\AutoDL\projects\作品\04-输出\成片\双人对决.mp4'
```

可选 `--fps 120` 或 `--fps 60000/1001`；`--dry-run` 只探测并显示计划。
脚本默认复用 `D:\mpv_lazy2\mpv\mpv-lazy` 的 **RIFE v4.6 + TensorRT FP16 + Turbo + 场景切换检测**，
对应已核实的 `MEMC_RIFE_NV.vpy` / `k7sfunc.RIFE_NV`。路径迁移时用 `--mpv-root` 指向新的整合包。
保持此算法，不擅自换成 SVPFlow、FFmpeg minterpolate、重复帧或其他 RIFE 模型。

脚本独立调用 mpv 的编码模式及 FFmpeg，不打开播放窗口，不修改播放器配置。
它会按源帧率计算到目标帧率的比例，而不是套播放器的固定2倍；不沿用播放器1440像素高度限制。
VFR或带旋转的视频先按原时间线规范化；HDR、超出当前引擎尺寸范围等不支持输入会明确报错，
不能悄悄降分辨率或改色调。源视频已达到/超过目标帧率时，脚本不重复插帧：已是60fps的最终文件核验后复用；高于60fps且要求默认60fps交付时，保留源片，另存保持时长/音轨/分辨率的60fps转帧率副本，不冒称RIFE补帧。用户明确指定其他目标时遵从。

默认输出 `原文件名-补帧60帧.mp4`，保存在**源视频当前目录**；重名自动使用
`原文件名-补帧60帧-版本02.mp4`，不覆盖已有文件。兼容MP4的音轨及mov_text字幕直接复制到MP4；
其他字幕、附件或特殊音轨使用MKV，并在结果里说明。mov_text与必须MKV的轨道组合在视频处理前拒绝，
须先明确兼容封装或字幕处理方案，不静默丢轨或转码；已达目标帧率核验后复用源容器。
作品内仍遵守项目中文命名；原片英文且无中文用途名时，由助手给出中文语义名，
通过 `--output-stem '中文用途名-补帧60帧'` 指定，不改原片。

运行可能较久；工具返回会话ID后继续轮询至完成，不把启动成功当导出完成。
首次遇到一种分辨率时，TensorRT可能编译本地引擎缓存；查看日志确认进展，不重复启动同一任务。
运行日志及结果记录保存在 `E:\AutoDL\.autodl\interpolation/`，中断/失败按记录排查；不自动换算法重跑。

## 验证与交付

动态复核遵循 `docs/工作流/multi-segment-video.md`「网页审片与辅助检查」：用网页播放器及浏览器专用通道，不调用桌面 Computer Use 或控制本机播放器。后台mpv编码导出仍按本技能执行，不等于允许打开其界面审片；未实际动态观看时不把技术验证写成视觉通过。

脚本会检查实际解码帧数、帧率、帧间时间戳、分辨率、时长、音轨数量/编码与音画相对起点，
并完整解码验证。验证通过才发布最终文件；失败不把半成品当成成片。
尾部垫帧只用于解决流式RIFE读取到文件末端时丢帧，最终按原时长裁切；不能把整段复制帧称为RIFE补帧。

已知多片段制作/接缝修复任务，还须依据最新时间线实际检查最终补帧文件全部N−1个接口，
把结果回填 `templates/short-drama/接缝验收.md` 对应的作品记录；检查窗口每侧至少2秒。
脚本的帧率/时间戳通过不能自动填视觉通过；发现停住、跳位或插帧异常须如实记录，未解决不宣称接缝完成。

完成后给用户新视频的完整路径链接，简述“源帧率 → 目标帧率、时长、原声保留”。
可抽查快速动作、遮挡和切镜处，不把补帧说成已修好原片中的人物变形、动作或剧情问题。
