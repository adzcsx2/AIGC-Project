# 本项目短剧流程

本项目采用用户指定的四阶段工作流。此文件负责衔接，创作方法使用已安装的原项目技能，
视频 API 使用现有 `autodl-aigc`；用户已放弃 Discord 接入，Docker 部署已删除，状态见 `docs/midjourney-local.md`。
先读根目录 `AGENTS.md`；清单格式与命令见
`docs/short-drama-workflow.md`。所有这里提到的路径相对本项目根目录。

## 1. 角色与画风

最新专项入口：用户以现成视频＋图片复刻时，转 `video-retargeting` 与已安装的
`clay-video-retargeting`，按源片长度、动作和镜头工作，不套本文件普通原创15秒多机位模板。
单图制作人物多角度与运动板时，转 `character-reference-board`：全身正背侧＋正侧脸＋实际运动格同图。
它的最新授权生图/验收与版式规则优先于下文旧的通用MJ和俯仰四格流程，其余短剧任务继续原流程。

本项目人物、角色板、3D CG打斗及相关画面提示词默认叠加
`s-grade-3d-prompts`（`.agents/skills/s-grade-3d-prompts/SKILL.md`），按用途取其人物材质、
多视角、动作镜头和特效方法。用户已明确打斗采用3D CG，不采用原文中禁止3D/CG的冲突负面词；
其他画风须用户明确另选。现有角色、场景和模型规则优先，不把历史例子当本次素材或生成授权。

建议保存名与实际素材遵守根目录 AGENTS.md：assets 下的目录、图片、视频、音频统一中文命名，
例如 `角色-银发法师-全身.png`、`镜头01-双人对峙.png`，内部资产和镜头 ID 不作为素材文件名。

- 有参考图：实际查看图片，记录身份、脸型、服装、配色和风格锚点，区分不可变身份与可变状态。
  仅凭文件名不能判断角色；无法查看时保持待检查状态。
- 只有参考提示词：提炼媒介、笔触/材质、色调、光照、镜头与渲染方式，再结合用户自己的角色需求。
  不把原提示词的角色身份、服装和故事自动带入新角色。
- 使用 `short-drama-assets` 和 `short-drama-image-prompts`，输出可复制的 Midjourney 图片提示词，
  本项目所有模型提示词正文统一中文，包含图片、视频、编辑、换角及负面提示词；用途解释与素材命名使用中文。
  按用户最新要求直接编写中文正文，API字段、参数枚举与协议引用标记保持原值。根据需要分别准备角色脸部、全身、造型、场景、道具、关键帧。
  本项目图片统一使用 Midjourney，默认 **V8.2**；交付中文提示词及挂图方法，由用户手动生成。用户明确指定其他版本时按其要求，不因沿用旧挂图方式自动退回 V7。
  每次交付普通 Imagine 生图用的可复制中文提示词时，末尾必须直接带上版本、画幅与 Aesthetics 参数（资产与分镜关键帧默认带 `--v 8.2 --ar <比例> --stylize 50 --chaos 0 --raw`；若某镜头或资产确需调整 `--stylize`、`--chaos`、`--weird` 等数值，直接写入提示词末尾并说明原因），同时明确网页端挂入的参考图顺序与槽位类型。V8.2 的人物与多图组合使用 Edit Model 的 Attach to prompt，Image Prompt / Style Reference 按用途选择；不套用 V7 的 Omni Reference 或 `--ow`，也不把 Image Prompt 的 `--iw` 当成 Attach to prompt 的权重。Editor / Layers 按 `docs/midjourney-local.md` 的编辑入口例外处理：当前Layer编辑实测不支持`--ar`，画幅由画布控制；其他后缀未核实则提供纯中文编辑正文及面板说明，不直接复用普通生图后缀。
  每张图片另按 `docs/midjourney-local.md` 的「逐图参数决策」与「每次交付格式」选择参考槽位、`--iw` / `--sw`、Aesthetics、SD/HD、Seed、排除项及 Personalization / Moodboard 状态，输出挂图表和中文参数卡；批量交付不省略各图设置。默认值只是生产起点，不把所有槽位或参数机械套满，不沿用 V8.2 / Edit Model 不兼容的选项。
  **每次生成或修改提示词后、正式交付前，必须执行二次审计**：逐条核对角色左右站位、面朝方向、肢体姿态、左右手持握、特效形态与位置是否完全符合分镜/用户需求，剔除与当前动作冲突的静态角色模板残留句，并检查所挂参考图（如站立镜头图 vs 空景母图）是否会束缚目标动作，同时核对参考槽位、权重、Aesthetics、面板状态、画幅与分辨率选择及版本兼容性。
  不再使用 Discord 用户 Token、代理、限速出口或网页自动化提交 MJ 图片，不为恢复旧任务重建部署。
  写出提示词不代表已有图片。不凭记忆编造当前 MJ 版本参数，需使用时查官方说明。
- **严禁碎片化单视角生图与拆碎短视频生成（用户强制要求）**：
  - **禁止错误方式**：严禁仅用单张正面/平视角色图，把一段连贯打斗或戏份拆成多张独立的单镜头静态关键帧，再拆成多段 3～5 秒各自锁死静态首帧的短视频（会导致跨镜头光影与透视跳变、模型因缺乏背面/俯仰参考而不敢转机位、成片变成生硬的“PPT 微动图”）。
  - **强制标准方式**：
    1. **角色多视角设定板**：角色基础外观确认后，依 `character-reference-board` 准备用户指定的全身正背侧、正侧脸与目标运动格同图；确有高低机位需要时补俯仰视角，也可用已确认多宫格连续分镜板。已有合格设定板不因版式更新强制重做。
    2. **普通原创戏份的15秒连续多机位视频**：使用实际支持的MiniMax入口将角色板和场景母图作为参考，按已确认分镜在单次连续生成内完成调度。仅此类原创方案采用已确认的`duration: 15`与多镜头指令；原视频复刻保留源片时间和镜头，不能套用本默认。
- **打斗受伤吃痛表现与中箭/伤势跨镜连续性（用户强制要求）**：
  - **任何人受伤必有吃痛反应**：任何角色只要在打斗中受伤（如中箭、被刃器劈中或贯穿），都必须写出可见可听的吃痛生理反应（身体受冲击后仰踉跄、眉头紧拧咬牙、同轨痛呼 `<d>[Chinese] ...</d>`、手掌按压伤口或抓握箭杆），严禁受伤时面无表情或毫无停顿反应。
  - **中箭/伤势跨镜头持续存在**：一旦箭矢、冰矛或兵器刺入角色身体，在后续每一个 `[Shot N]` 描述该角色时都必须显式复述该箭矢/伤势仍插在原位（遵循 `h3-storyboard` §四之三“每一颗镜头都要重新供给状态”），严禁中箭后下一秒箭矢凭空消失。
- 用户因封号风险明确放弃 Discord 方案，旧容器、专用镜像、网络和部署文件已删除；手动生图继续。
- 用户最新要求选定后自动推进与多提示词批量交付：用户选定/确认后立即归档并执行已确认计划的
  下一必要步骤，不再重复询问“是否继续”。**若后续多个场景或分镜关键帧的前置条件（如分镜已定稿、所需角色与场景母图已就绪）均已满足，应一次性将所有满足条件的多场景/多镜头可复制中文提示词、参考图挂法、Aesthetics 参数与中文保存名批量交付给用户，而不是拆成单张逐一验证；用户可一次性返回多张选定图片，助手统一完成看图验收与中文归档后再进入下一步。**
  不把连续制作授权解释为仍可自动提交 MJ 请求；需要用户手动生成时交付明确材料后停下。
  不替用户选图，不擅自U/V/R或扩展计划外图片；视频仍先满足素材与模型/预算条件。
  助手看图不能替代用户验收；未经用户选定的文件保持待确认，不登记ready；选定后也不在该节点无故停下。

## 2. 想法到剧本和分镜

- 需要故事开发时使用 `short-drama-develop`；已有完整剧本可直接进入后续阶段。
- 使用 `short-drama-write`、`short-drama-storyboard`，维护每集五份正文：
  `剧本.md`、`视觉设定.md`、`分镜.md`、`图片提示词.md`、`视频提示词.md`。
  需要项目初始化或查看创作进度时才使用 `short-drama` 的工具。
- 分镜明确人物、场景、景别、机位、动作、情绪、台词、时长、起止状态与必要参考素材。
  打斗戏先用 `fight-scene-design` 主动补齐动作、运镜、打击反馈、特效与声音，再按需调用
  `martial-arts-director-cy`；H3 情绪与动作密度可参考 `h3-storyboard`。
  后者的小样本指标是经验，不承诺模型一定执行精确动作、切点或表情。

## 3. 补图与就绪检查

- 按真实镜头列出所有缺少的角色、场景、道具、起始/结束关键帧与必要声音素材：
  稳定 ID、缺少什么、影响哪些镜头、用途、可复制提示词、预期保存路径。
  有可用图就复用，不能仅为凑满槽位新增需求。
- 用户补图后实际查看，核对身份、画风、构图、角色站位及镜头起始状态。符合且用户确认后才登记 `state: ready`；
  `provided` 表示有文件但尚未检查；`missing` 表示待补。`PLAN-...` 和图片提示词均不算现成素材。
- MJ 原始下载先保存在 `outputs/midjourney/`，选定成图后按中文名称归档到 `assets/作品名/`。
  历史任务与尝试记录位于 `.autodl/midjourney/`；仅离线查阅，不恢复代理或重新提交。
- 创建/更新每集的 `materials.yaml`：只登记文档与素材就绪状态、文件路径及镜头输入绑定；
  剧情、画面和提示词正文仍以五份 Markdown 为准。变更剧本/造型/镜头后重新检查受影响的就绪状态。
- **用户明确要求素材满足后才能进行第 4 步。任何必要图片缺失或不匹配时，交付补图清单后停在这里。**
  此要求覆盖原技能允许带 PLAN 槽位继续下游的默认行为；不得默默改走文生视频。
  不自动调用其他图片生成商替用户补图。

## 4. MiniMax 图生视频

原视频驱动的换角/动作迁移先使用 `video-retargeting`，其 H3 专用角色替换使用简单提示词，
不套本节普通图生视频的六段式。清单中的视频登记为 kind: video 并绑定实际媒体字段。

- 仅素材齐备后使用 `short-drama-video-prompts` 的 MiniMax H3 方言编写最终视频提示词，
  再用 `autodl-aigc` 查询实际工作流规则、价格及参考方式，逐镜编写 YAML。
  上游示例 production_profile 的时长范围不是 API 规则，使用本项目实际 `input_rules`。
- 每个短剧镜头配置必须同时写 `materials_manifest` 和 `shot_id`。先执行
  `autodl materials check 清单路径 --shot 镜头ID`，再执行 `autodl validate 镜头配置路径`。
  缺少任何必要素材、状态未就绪或媒体字段绑定错图时都不能提交。
- 提示词图片编号与 API 字段按实际顺序对应，如 `<Picture 1>` 对应 `ref_image_0`；
  角色/场景参考与首尾帧按模型实际支持选择，不能向首尾帧工作流强塞多图参数。
- 不安装或虚构 `$short-drama-produce` 的 provider/adapter，也不因上游引用它而停住；
  本项目投产由 Python `VideoProject.generate` 经 AutoDL 完成。
  上游 `h3-storyboard` 提及的 `minimax-h3` 技能语法职责由已安装的 H3 方言参考承担。
- 用途、镜头、时长、分辨率和预算在用户授权范围内时执行生成，保存 task_id 后等待、下载与检查。
  没有付费授权时停在配置与离线预览；不从这次安装请求推定生成授权。
  不重试创建结果不确定的 POST，使用已有任务恢复查询。

需要复核剧本或镜头质量时使用 `short-drama-review`；需要扩展能力时使用
`short-drama-skill-finder` 从索引核对真实源仓库，再安装匹配的具体技能。
小说拆解和后期剪辑未安装；原片需要拆镜、抽帧时已可使用 short-drama-breakdown。
