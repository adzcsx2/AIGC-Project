# 总导演流程

人物与声音遵循 `docs/工作流/character-voice.md`：每人独立YAML，显示名不自动成为剧情称呼。仅剧本需要人物说话时才要求配声，无台词/非语言声不列队列；需要说话却未配声时列队列，先完成独立工作，最后集中请用户配置/试听；接受后按人物ID、声样哈希复用并继续依赖步骤。声音等待不重启文案/选图确认，不自动使用随机音色。

先读根目录 `AGENTS.md` 与 `docs/工作流/director-workflow.md`；清单与命令见 `docs/工作流/short-drama-workflow.md`。
所有路径相对项目根。这里负责阶段交接，具体摄影、资产、API各只有一个入口。
审片遵循 `docs/工作流/multi-segment-video.md`「网页审片与辅助检查」：默认网页原速播放，可用真实非桌面直读能力；禁止桌面 Computer Use 及失败后自动切本机播放器。抽帧、技术检测和ASR不能冒充动态/听音验收。
按 `docs/skill-routing.md` 接收跨阶段任务，持有当前作品、确认节点和下一交付。单项只改镜头/表情、查API、做参考板或恢复task_id直接交专业技能，不重启全流程；协作顺序按依赖，已有合格输出跳过。

声音按 `docs/工作流/music-postproduction.md`：新原创视频生成默认仅已有对白、无音乐，无对白默认静音；环境声/音效需明确要求，原片明确保声任务优先。第3步记录后期音乐意图与留白，第5步审计视频提示词没有混入后期配乐要求；第6步在剪辑完成后按真实全片时间校准cue、制作独立音乐并混音，再交补帧。助手决定音乐的叙事用途与进出，不按生成段各起一首；音乐制作入口未核实不得标ready。独立只配乐任务直接进入这一后期阶段，不重启剧本、生图或视频生成。

写、补、改剧本前必须读取 [电影级剧本基准](../cinematic-script-audit/SKILL.md) 及其检查清单，再使用动作/运镜技能。默认16:9横屏，生成和剪辑默认24fps，最终成片自动补到60fps，不考虑平台UI安全区域；用户指定及已确认规格优先。流程第5步完成总审计并修正后，才可在第6步交付最终审图/生成提醒；**禁止等用户说“确定生成”后才总审计**。确认后仅核对已审版本和技术输入，已有授权不重复确认费用。

1. 查用户目标、已确认文案及素材用途：要求保留源片动作/运镜换角才交 `video-retargeting`；只测量/拆解用 `short-drama-breakdown`，只借风格或镜头参考仍是原创。不能仅因附有视频就切到复刻。
   读取本片 `project.yaml.documents.style` 与实际风格基准，按导演流程「项目风格与防漂移」补齐现有视觉设定并锁定本次来源版本；交图片/摄影落实到每个请求，提交前核对实际正文。生成后执行风格一致性专项，覆盖各源段首中尾、近景/换角度、接缝和最终版，不改批量生成顺序、不新增默认剧情/表演全项审计。
2. 文案/动作不足时先主动写中文补全稿，保留用户人物、意图、结果和风格；打斗交 `fight-scene-design`。
   按根规则及导演流程「表情、情感与镜头表现」，在剧情阶段写明情感触发、表情和肢体变化，交摄影设计相应镜头变化；不等写提示词时再笼统添加“表情丰富”。
   涉及舔饮、抓握、踩踏或碰撞等互动时，按同文「真实接触与物质反馈」写清接触、对象响应及后续状态，交摄影保证关键因果可见。
   原创连续打斗默认采用其高密度导演合同，先核对双方资产、攻击手段、状态接力与时间容量；这属于同一打斗入口的方法，不另启一套流程。
   写清新增细节、时长与真实缺口，先取得用户确认，再开始正式分镜/提示词/制作。
   不边等确认边制作；完整明确或已确认版本不重复问。确认元数据见新schema 2清单。
3. 确认后 `storyboard-camera` 按 `docs/工作流/multi-segment-video.md` 先审计模型段内切镜、首尾图分段或混合方案，决定段数、每段秒数与理由，再逐小段选镜并审计整体多样性。
4. `visual-assets` 检查资产与缺口；新人物、动物及其他生物必须先交 `character-reference-board` 生成/验收独立三视图，只含正面特写、正面全身无头、背面全身，不随动作需求加视图。随后以三视图制作含角色的场景/镜头图，交autodl按 [人物流程](../../../docs/工作流/character-voice.md#新角色三视图前置与api绑定) 将三视图实际绑定API身份输入；不能只传场景临时生成的角色。已有同身份合格板复用，无身份依赖的工作继续。
   多片段按2026-11-11的跨段切镜规则在剧本/分镜/提示词中预设计可见转场，速度连续链尽量留在≤15秒同一次生成内。按镜头准备前出后入的不同构图及必要端点，不再默认N−1张共享图；规则只在multi-segment-video.md维护。按实际用户/作品限定自主验收授权实看归档，再交第5步总审计及已授权生成，不伪造逐图用户认可。
5. 人物戏默认自动调用 `acting-prompt-writer`，在已确认镜头/动作内丰富表情、情感与肢体反应，保留台词与大动作；与摄影和打斗技能分别负责人物表演、画面覆盖、招式，不另起剧情。`storyboard-camera` 整合并二次审计视频提示词，检查表演细节、情绪递进、有效镜头变化、主攻击覆盖与招式变化是否落实且中英文一致；`autodl-aigc` 提前核实真实配置与能力，随后由 `cinematic-script-audit` 总审计当前全部方案并修正，记录版本、证据与结论。必要缺口未解决时不发生成提醒。
   视频默认优先u30（用户2026-11-11）；按导演流程用途表核实真实能力。u30当前无参考视频或专用首尾帧，必要输入不兼容时先说明并由用户选择接口，不静默降级；白模仍先做，仅本地规划与实际上传分别记录。
   提示词审计按导演流程「提示词迭代审计」反复修稿与复核到全部适用标准通过，包含接触/碰撞/液体反馈；不把“二次”当次数上限，不交付未通过稿为最终提示词。缺证据或待用户决定项如实列出，继续独立修正，不以降低标准或自动重抽结束循环。
6. 先展示第5步总审计结论，再交最终审图/生成决策材料；用户接受同一方案和图片后，`autodl-aigc` 核对已审版本与输入，直接提交所有计划片段，每段一次，按平台能力批量/并发。单段同样先审计后提醒；不再逐段等实际尾帧或助手审片。下载后做必要技术检查，并按 `docs/工作流/multi-segment-video.md`「所有接缝交付前必查」逐一检查N−1个接口的源端与真实合成结果。按已审切镜/转场选出入点并剪掉多余等待；旧片或明确连续例外再按版本04匹配运动切点、保留必要过渡并按需局部压短；音画合成后自动调用 `补帧` 到60fps，再复查全部接口。填写 `templates/short-drama/接缝验收.md`，全部通过才报告接缝完成；整体创作状态保持待用户验收，不扩成全片审美审计。
7. 用户明确要求重做某段时只生成该段，用户认可替换段后自动重合成；其余片段与旧版保留。影响共享边界图的修改先说明范围。用户另行要求时才做针对性视频创作审计。

用户仅反馈多个片段卡顿时，从当前已有码流和映射进入第6步：检查全部接口，不只检查点名的第一处，不重启文案/图片/付费生成流程。安全修剪须保留必要动作、音画同步并披露实际时长；无法安全修好时记录具体接口，不用静帧凑时长或自动收费重抽。

后续新多片段按已设计切镜/转场合成；旧片或用户明确连续镜头例外采用版本04方法，见 `docs/工作流/multi-segment-video.md`「既有连续镜头剪辑：版本04方法」：匹配运动中的切点，保留必要中间姿态并局部压短收势/启动/重复准备，主体原速、音画同步，再自动调用 `补帧` 到60fps并复查全部接口。不能只删长静帧就交付；倍率、切点按当前素材判断，已流畅的接口不强改。用户认可成片后登记对应版本/哈希及确认原话，不再让用户重复验收同一节点，也不因此另起生成。

最终60fps交接也适用于单段成片及替换后重合成，无需用户再点名；已是60fps则核验复用。用户明确另定帧率或不补帧时遵从。原始归档、中间预演、仅查询/下载原始结果及规则维护不触发；不在旧补帧版上反复插帧。

## 按需取内部资料

- `.agents/resources/skills/short-drama-develop/references/`：短故事结构与时间容量。
- `.agents/resources/skills/short-drama-write/references/`：场次、戏剧动作和对白；正文拥有权是 `剧本.md`。
- 新作品用 `.venv/Scripts/python.exe tools/项目.py init 中文作品名` 创建 `projects/<中文作品名>/project.yaml`，再按 `docs/规范/目录与命名规范.md` 和当前生产模板按需建目录、填写文件指针；已有作品直接读取其入口，不重复初始化。`.agents/resources/skills/short-drama/` 的旧管理脚本与模板仅作方法和历史资料，不用于建立当前项目状态或目录。
- `.agents/resources/acheng-director/references/11-story-architecture.md`、`10-scriptwriter-engine.md`：故事推进。
- `.agents/resources/acheng-director/references/80-continuity-ledger.md`：状态和因果。
- `.agents/resources/skills/short-drama-review/references/`：按当前阶段自动审计；不读完整资料包才开始。

内部源文件的旧语言/工具/强制版式不覆盖本项目。五份Markdown为创作正文，materials为状态绑定；
Acheng production.json只从已确认文档派生，不能形成双份互相冲突的剧本。
新视频默认先做简单白模：原创交`blender-video-original`，源片重建交`blender-video-recreate`，优先本机`D:\blender-5.3.0\blender.exe`。合格已有白模直接复用；用户明确例外、纯文件处理和预演/接口输入分工见[共享规范](../../../docs/工作流/白模制作与验收.md#默认先做白模)。huashu-seedance仅承接指定旧流程，不承诺任意视频自动动捕。
