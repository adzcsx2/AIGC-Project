# 审计方法与输出

这是 `review` 的取证与报告方法。执行时读取当前项目规范；下表帮助选择检查维度，不复制专业清单，不固化模型参数。具体技能职责和交接只在 [项目路由](../../../../docs/skill-routing.md) 维护。

## 按内容选用检查维度

| 内容/条件 | 要回答的问题与证据 | 现行依据入口 |
|---|---|---|
| 所有文案 | 谁读、用来做什么、关键意思能否直接理解？事实、术语、指代、逻辑、语气、信息顺序是否一致？是否漏必要条件、前提或结果，是否有冗余、空泛形容和无法兑现的承诺？ | 当前用户要求、已提供事实和目标文档的规范；无作品依赖时不套视频规格和视觉风格 |
| 故事、大纲、剧本、对白 | 人物为什么行动，冲突如何推进，铺垫是否兑现，观众何时获得关键信息，结尾是否有结果与反应？对白是否符合人物关系与潜台词，正常速度能否说完？ | [电影级基准](../../cinematic-script-audit/SKILL.md) 与其检查清单 |
| 表情、情感与肢体 | 有什么触动、情绪怎样变化、怎样被看见？说话者与倾听者是否都有情境反应？是否反复点头/微笑或把一切降成微表情？远景是否硬塞不可见细节、非人角色是否套了不存在的器官？ | [人物表演](../../acting-prompt-writer/SKILL.md)；[导演流程](../../../../docs/工作流/director-workflow.md)「表情、情感与镜头表现」 |
| 分镜、摄影、转场 | 每镜揭示什么，机位/景别、跟随主体、路径/速度、焦点、切出触发是否具体？主动作、接触与反应能否入画？镜头变化是否服务信息和情绪？ | [分镜与摄影](../../storyboard-camera/SKILL.md)；其运镜参考与现有运镜审计模板 |
| 日常动作、抓握、碰撞、液体互动 | 启动、路线、接触位置和时间是否明确？受作用对象有什么合理反馈，结束后保留什么状态？重量/支撑/物质转移是否成立，镜头能否看见关键接触？ | [导演流程](../../../../docs/工作流/director-workflow.md)「真实接触与物质反馈」「主体与物体的尺寸约束」；非打斗动作不强套攻防模板 |
| 所有适用动作的速度（独立必查） | 决斗/攻防、追击、跑动、跳跃、转身、伸手等主动作是否按合适的正常速度执行？片长和动作耗时是否分开，准备/发力/接触/回收是否被拉慢或停住？镜头、特效、60fps是否掩盖人物本身的缓慢？ | [速度与真实物理时间](../../../../docs/工作流/白模制作与验收.md#速度与真实物理时间)；攻防另读fight规则，明确慢镜/时停/悬停和源片保留例外不机械取消 |
| 体型、身高与起落高度 | 比较的是同姿态体高/体长、屏幕外框、重心还是脚下间隙？尾翼是否计入？同框参照、实际相机/透视和前中后段是否相容？差异是否可能来自抬头/站直/展翼或分割误差？ | [尺寸约束](../../../../docs/工作流/director-workflow.md#主体与物体的尺寸约束)及白模共享规范；二维候选不能证明完整3D体积恒定 |
| 打斗、施术、追击 | 是否有战术意图、身体启动、传力、路径、对手同时应对、命中/闪避、反馈和承接？距离是否真实闭合，伤势是否延续，变化是否超出左右换招？速度强调是否符合本场规则？ | [打斗设计](../../fight-scene-design/SKILL.md) 及按需引用的动作/空间因果/高密度合同；不把示例时长和招数变成配额 |
| 人设、场景、视觉与风格 | 当前身份、服装、身体结构、场景锚点、尺度、材质和光照是否一致？身份、环境、风格参考是否各司其职，实际英文正文是否继承本作品风格？ | 本作品 `project.yaml.documents.style`、人物YAML与认可基准；[视觉资产](../../visual-assets/SKILL.md)；涉及角色板时再读 [角色板](../../character-reference-board/SKILL.md) |
| 跨镜、跨段与时间容量 | 前一拍留下的空间、方向、持物、伤势、情绪和环境后果是否成为下一拍的条件？剪切能否保留因果，跨请求边界是否预设可见切镜/转场？对白、动作与镜头是否争抢同一时间？ | [多片段流程](../../../../docs/工作流/multi-segment-video.md)；已确认分镜及相邻段落。审设计时不能假称实际接缝流畅 |
| 对白、声线、配乐意图 | 是否保留原台词与说话人；生成期声音和后期音乐是否分开；是否无故要求沉默角色配声；缺声音会影响哪些后续镜头？ | [人物与声音](../../../../docs/工作流/character-voice.md)、[后期配乐](../../../../docs/工作流/music-postproduction.md)；当前明确保声例外 |
| 图片/视频/编辑提示词、生成方案 | 中英文、素材顺序和实际输入是否一致？每个请求是否落实适用约束？静态模板是否妨碍动作，时间与输入容量是否支持设计？ | 对应专业技能与 [AutoDL执行入口](../../autodl-aigc/SKILL.md)；以真实契约核实，不把文本里的“4K”或fps当真实参数 |
| 白模或保留原片的设计及已有视频专项 | 白模准确承载哪些尺寸/路径/速度/接触/摄影控制，哪些细节交模型？实际参考/白模/请求/原生/最终是否对应？角色姿态、背景/机位是否漂移，偏差来自输入、模型还是后处理？ | [白模规范](../../../../docs/工作流/白模制作与验收.md)、[动作迁移](../../video-retargeting/SKILL.md)、[原片测量](../../short-drama-breakdown/SKILL.md)；按阶段核查并遵守网页审片，不因审计自动制作 |

只读当前内容适用的资料。遇到表中未覆盖的文案类型，按 [安装清单](../../../../docs/installed-skills.yaml)、实际技能目录和项目路由寻找相关标准并实读；无合适专业入口时说明缺口，仍完成一般文本审计，不虚构已安装的技能。第三方资源和历史实例只取方法，不作为本次授权或当前事实。

## 动作速度与白模视频专项取证

适用于当前审计中的动作设计、分镜/提示词、白模和已提供视频。规则正文沿用上述专业依据，本节维护review怎样取证和出结论，不另设通用厘米数、动作秒数或速度配额。

1. **按阶段核对速度。** 剧本/文字阶段检查动作节奏、正常速度意图及慢镜冲突；可执行分镜/白模方案检查实际位移和阶段秒数；已有媒体检查真实执行。按当前审计范围逐个主动作和连续动作链核对，重复项可合并记录覆盖范围，不能只审一跳、一个重击或少数代表镜头后声称全段速度通过。缺媒体不阻断纯文本可判项，但对应实测保持待核实。
2. **按动作机制找慢点。** 决斗核对距离闭合、启动→武器加速→命中/格挡/闪避→反冲/回收是否拖长、摆姿或反复停启，慢速强调是否仅在已确认白名单。跑动核对位移、步频、步幅和支撑；跳跃核对起跳、重心/最低足轨迹、顶点、落地和缓冲，持续拍翼等按作品受力机制；转身/伸手等按对象、重量和意图检查。不能把所有动作强行加快，也不把“快速”字样当实测结果。
3. **锁定实际证据链。** 按当前对象记录真实参考、白模/工程与采样、实际请求配置/素材绑定、原生结果和最终处理版的版本/哈希。核对真实接口能消费哪些控制信号、哪些只是本地规划或软参考，源图片/输入用途不互相冒充。原有已提交记录保留，缺服务端跟踪/分组证据时不臆断唯一内部原因。
4. **统一尺子与时钟。** 写清体高/体长、尾翼范围、同场参照、相机/透视及可比姿态；将最低足距地、重心轨迹和外框变化分开。按实际fps/PTS定位主动作开始、峰值/命中、落地和恢复，比较位移与耗时及速度/加速度趋势。报告测点、单位、帧号/时间和误差；颜色掩码连接到翼尾或旁人时只作候选，不能据此证明3D体积或精确世界厘米。
5. **原速对照并归因。** 对已有白模和原生/最终视频按网页规则以1×观察完整动作及关键阶段，核对动作速度、物理反馈、角色状态、背景布局/机位和风格。白模速度作为生成前独立放行项，检查实际送模版本的位移/耗时、插值/速度曲线及原速观感；只核最高点/几何或看另一审片版本不够，复用输入同样要核对。若引导本来慢升/长停，先修输入再复核，不带病交模型或以补帧补救；若只有生成片偏离，说明模型执行误差；若最终版时长/相位改变，查编码/补帧/变速。数值、抽帧和技术检查不能取代动态证据，正常速度也不能只由“无重复帧/高帧率”推定。
6. **逐项给结论。** 至少将适用的尺寸/姿态、速度/物理、真实输入和状态稳定性分开，明确设计判断或实际测量。初始大小接近不等于全段恒定；几何/最高点通过不等于速度通过；某次背景稳定不等于接口有冻结能力。必需项失败不被其他通过项抵消，未实际看/量的项不写通过，也不把专项通过升级为用户整片认可。

已有媒体不因发现问题自动变速、补帧或重生成；按当前授权交具体修法、修订文本和复核。若确需用户决定新的剧情/摄影或制作路线，保留待决定；不要把“修到通过”解释为无限付费试跑。

## 证据、遗漏与冲突

第一轮固定本次要求、原稿版本和授权范围，每轮按当前版本重新建立覆盖对应：`要求/来源 → 适用阶段/范围 → 正文或输入位置 → 验收证据 → 状态`。每项用户明确要求、已指出的问题与必需标准都要有归属。短稿可用几句话，长稿或跨文档任务再用表；覆盖、一致性、提升空间是每轮都适用的检查方向，不各自算一轮，也不以轮数代替质量证据：

1. **覆盖**：逐项找证据，包含未写出的需求、结果、承接和对象反馈；不能因为没有相关文字就直接写不适用。
2. **一致性**：核对句间、镜间、版本间与真实输入的关系。位置、左右手和屏幕左右须按同一空间理解，不能把合理换机位当穿帮；也不能用切镜解释瞬移或状态复原。
3. **提升空间**：比较少量可行修法，选择能改善本次目标且不会破坏保留项的方案，交具体收益和代价。若原稿已经有效，明确保留，不制造改动。

证据定位使用文件路径＋章节/镜头ID/时间范围/短原句，留档时记录输入版本或SHA-256。用户直接提供的文本可标“本轮提供稿”；不要伪造文件、行号、时间码、确认来源或哈希。引用规则时说明为何适用，不只罗列技能名。

事实性主张以用户提供的可靠依据或可核查来源判断；涉及会变化的事实和接口能力时读取当前证据。来源不足则标待核实，不因语句通顺就背书真实性，也不擅自补入未证实的信息。

严格区分“未写清楚”“有矛盾”“缺外部证据”“可选提升”。角色已经有合格三视图但本次没读到时是待核实，不能断言未制作；稿件明确使用错误版式时才可判文本不符。只审剧本时，未生成的资产列后续制作依赖；若用户同时要求可提交方案，缺关键资产/真实输入就影响就绪结论。

适用例外也需证据：指定极简表演、固定镜头、既有画风或保留原片可以改变默认检查结果；不能只为省事写“不适用”。历史已提交稿按当时依据复盘，新建议另列，不倒改记录；用户要新版本时才按当前要求设计新稿。

规则冲突记录双方位置、范围与更新依据、采用判断和影响。确认不了的实质冲突只阻塞依赖它的部分；不能把一部作品的尺寸、特许或角色外观推广给所有作品。模型相关资料互相冲突时，按当次真实契约解决能力问题，不选最宽松的描述放行。

## 问题分类与输出

必需性与处理状态分开。问题可归为“必须修正／待核实／待决定／可选优化”；处理后记录“已修并复核／未解决／未核实／待决定／采纳或保留及理由”。这样不会把已提出的建议误写成已修复。

先给最影响目标的结论，报告随任务规模缩放：

- **范围与依据**：固定原稿基线、最终版本和全部审计对象；必须保留什么；实际读取了哪些规则和参考。
- **发现与修订**：包含遗漏，按影响排序；重复问题合并并列影响位置。
- **优化稿**：原结构中的修订版或准确替换段落；只审不改模式改交建议，待决定内容单独标记。
- **复核与遗留**：验证实际修改，核对相邻/全局影响，说明缺证据或待决定项及后续补法。
- **五轮记录与门槛**：实际完成轮数、每轮完整范围/证据/发现/修订/结论；最终验收状态计数和未覆盖要求数；区分文本、媒体实测与整体 `CLEAN / BLOCKED`。
- **动作/媒体专项结论（适用时）**：列动作/时间范围、尺寸/速度定义、期望与实际证据、误差及结论；速度必须独立报告，分别标明设计判断、白模实测、原生/最终实测和待核实项，不用一句“整体流畅/电影感”代替。

长稿可采用下表；没有的问题不用凑数量。

| 编号/分类 | 原文位置、原句或缺失位置 | 依据与影响 | 实际修订或待决定方案 | 复核证据/当前状态 |
|---|---|---|---|---|

验收对应始终需要，表格按任务规模选用；每轮重新判断，不能只更新上轮失败行：

| 要求与来源 | 适用段落/阶段 | 当前正文/真实输入或缺失 | 验收证据与版本 | PASS / FAIL / NOT_VERIFIED / BLOCKED |
|---|---|---|---|---|

`FAIL`表示已有证据证明不符；`NOT_VERIFIED`表示必要证据尚未验证；`BLOCKED`表示依赖用户决定、缺失文件或无法完成的必要检查；仅证据充分支持当前要求时才记`PASS`。不适用项单列理由，不混入PASS计数。缺证据不是已证实的缺陷，但同样不能通过该项。

可选优化需交代收益和代价，例如反应镜头改善情感可读性却占用动作时间；不得在“台词不变”条件下用删台词腾时间。若没有值得采用的优化，直接说明保留的设计及理由，不空泛赞美。

## 五轮记录与最终结论

轮次、完整复审、修订权限和停止门槛按 [review入口](../SKILL.md#五轮循环放行与停止条件)执行，沿用 [提示词迭代审计](../../../../docs/工作流/director-workflow.md#提示词迭代审计) 的证据闭环。本节只维护报告格式，不另立生产状态或再启动一套循环。每轮先独立检查当前完整范围，再核对旧问题是否实际消失；旧发现仅作进度追溯。

默认做满5轮；每轮一行，提前遇到不可解决的阻塞则只列已执行轮次并说明停止原因。无问题的前几轮标“本轮未发现问题，待完成剩余轮次”，不能预填最终通过。建议简表：

| 轮次 | 本轮完整范围与版本 | 证据/检查 | 问题（新增/遗留） | 实际修订及修后版本 | 本轮结论 |
|---|---|---|---|---|---|

最终汇总包含：

- 固定基线、最终版本、约定/实际轮数及最终完整审计覆盖的对象。
- `PASS / FAIL / NOT_VERIFIED / BLOCKED` 必需验收行数量、未覆盖要求数、未解决实际缺陷数；轻微错误同样计入，纯可选审美优化另列理由。
- 实际修订和验证结果，以及最后一次内容/输入修改是否早于最终完整审计。第5轮后才修正的版本不能继承修前结论，标 `BLOCKED` 并说明尚缺新的完整审计。
- 文本/设计、适用媒体专项的分层结论，以及整体 `CLEAN / BLOCKED`；提前阻塞、只审不改或剩余缺口须说明具体解除条件，不把部分完成写成全部通过。

复核尤其检查：修接触是否引入了新物品或不可能的身体动作；补表情是否改变台词、主动作和时间；改机位是否破坏空间、动作覆盖或既有素材；调整一段是否影响前后段、声音和英文编译；文本改动是否使旧确认及审计依据失效。不要以新发现为由改掉不在授权范围内的内容。

分层结论按证据使用 `本次文本/设计范围通过`、`本次媒体专项实测通过`、`需修正`、`待核实` 或 `待决定`。媒体专项通过必须有对应实际查看/测量依据，不由文案结论推得，也不等于用户整片验收。只有做满约定轮数、最后一轮无遗留实际缺陷、全部本阶段必需验收项为PASS且适用验证通过，整体才能为 `CLEAN`。仅属于后续阶段的依赖不阻断本次纯文字通过；若本次包含媒体/提交就绪要求，缺证据时整体保持 `BLOCKED`，可独立说明文本通过。只审不改模式按原稿结论交付，不为达成通过擅自修改。

未通过提示词在标题和正文附近标明“草稿／未通过，待解决哪些项”；不能一边列必要缺口，一边提供标为定稿的提交正文。修订稿通过但改变了确认内容时，明确它是候选版本，不能声称用户已经接受。

生成提醒前总审计沿用 [电影级审计模板](../../../../templates/short-drama/电影级生成前审计.md) 和对应技能，不用本表替代；实际播放、听音、物理反馈及风格一致性由真实输出验证。技能结构检查、场景推演和文案通过都不能证明成片效果。

## 多主体参考图序专项

对照实际图片槽位/序号、角色ID、白模起始位置、身高/同框图排列和英文映射，检查默认图序配对冲突；只检查prompt中左右是否正确不够。按[图序与空间映射](../../../../docs/工作流/video-retargeting.md#多主体图序与空间映射)先重排输入/图内布局再审，区分已知输入冲突与尚未证明的模型原因，保留历史提交，候选修正不等于授权重抽。
