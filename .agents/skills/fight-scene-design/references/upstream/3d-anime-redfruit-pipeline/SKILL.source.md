# 3D动漫红果原生多镜三步骤流水线

输出可生成、可剪辑、可拆分回退的v4单段整合版分镜。战斗速度必须通过可观察的动作先后、距离缩短、接触、受力、恢复和镜头切点体现，不靠删除动作、改台词或堆叠无动机切镜加速。

## 即梦提示词可执行性规则

“红果高速”“红果式”“攻守反转”“压迫感”“情绪落幅”“爽点”“电影感”等是内部编排标签，不是视频生成指令。它们可以出现在工作层的路由或分析中，但不得写入用户可直接投喂的标题、【大场景】、【画面】、【节奏功能与状态变化】或其他生成字段。第五节【风格词缀】允许使用用户指定的固定开头“4K画质，电影级3D游戏CG概念风格”，但后续仍必须用具体动作、镜头、光线、声音和材质替代空泛形容词。即梦提示词也不要依赖“电影感”“高速”“史诗”等抽象词来传达效果。

最终提示词必须把标签翻译成可观察载体：速度写明确秒数、动作顺序和镜头运动；双方变化写谁从哪一侧向哪一侧移动、是否接触、谁后退；压迫写机位高度、主体占比、距离和出口；情绪写眼神、眉眼、嘴部、呼吸和重心；节奏写切点、声桥和唯一结果。若一句话无法被摄像机、录音机或秒表直接观察，就改写为角色动作、镜头、光线、声音、材质或约束。

## 权威文件与读取顺序

执行前按当前场景读取：

1. 始终完整读取 [references/core-workflow.md](references/core-workflow.md)，确定三步骤、v4投影和原生多镜格式。
2. 战斗、追击、斗法、召唤、变身、爆炸或破坏场景完整读取 [references/redfruit-pacing.md](references/redfruit-pacing.md) 与 [references/combat-causality.md](references/combat-causality.md)。纯文戏不强制读取这两份。
3. 有台词、表演或情绪任务时完整读取 [references/emotion-performance.md](references/emotion-performance.md)。
4. 始终完整读取 [references/master-shots-multicut.md](references/master-shots-multicut.md)，为内部切镜建立约束与覆盖图。
5. 当剧本明确出现异能、元素/能量操控、念力、空间能力、法相、内力场、护体罡气、能量兵器或类似玄幻特效时，读取 [references/ability-fantasy-combat.md](references/ability-fantasy-combat.md)。仅在原文或用户要求出现这些能力时启用，不得擅自新增能力体系。

格式冲突以 `core-workflow.md` 为准；节奏以 `redfruit-pacing.md` 为准；攻防结果以 `combat-causality.md` 为准；台词字词和人物表演以 `emotion-performance.md` 为准；镜头选择以 `master-shots-multicut.md` 为准。
异能与玄幻特效的视觉层级、能量生命周期、兵器特效和法相绑定以 `ability-fantasy-combat.md` 为增强规则，但不得覆盖用户固定事实、攻防主结果、轴线连续和唯一峰值约束。

## 默认参数

- 转化模式：无损；
- 战斗节奏：连续动作密度；文戏节奏：自然对白节奏；这些只用于内部路由，交付字段改写成可见动作链。
- 单个外层镜号：按连续动作簇实际需要确定，总时长大于0且不超过15秒；15秒是上限，不是固定目标；
- 战斗镜号：先合并连续分镜，再安排至少6个真实内部切镜；通常控制在6—10镜，复杂但仍可读的15秒动作簇可扩展到11—12镜；日常剧情、普通文戏和生活段落保持4—6个内部切镜；
- 画幅：16:9；用户明确红果竖屏时改为9:16；
- 单镜最多3名发声角色；
- 中文描述加必要英文镜头术语；
- 不新增旁白、招式、境界、胜负和人物。

## 冲突优先级

1. 用户本轮明确要求；
2. 剧本固定事实、事件顺序、原始动作和逐字台词；
3. 已确认人物、场景、武器、能力、伤势与首尾帧资产；
4. 目标平台的时长、原生多镜与音频能力；
5. v4输出契约与三步骤顺序；
6. 连续动作簇与状态变化节奏；
7. 攻防、特效和物理因果；
8. 大师镜头技巧与视觉风格。

低优先级不得覆盖高优先级。节奏压缩只通过同步、动作匹配、声桥、缩短无效等待和重新分簇实现。

## 强制三步骤

### 第一步：剧情、账本与节奏

- 逐句建立固定事实、逐字台词、动作、武器、伤势、站位、光源和特效账本。
- 战斗场景先找出威胁、距离、优势、能力、伤势、目标和信息变化，再按同一目标、轴线和连续动量组合动作簇。
- 先把同一目标、同一轴线、同一空间区域和连续动量下的多个分镜合并；合并后总时长不超过15秒时，不因单个动作动词而拆成多个外层镜号。
- 一个战斗镜号至少含6个真实内部切镜，通常为6—10镜，只有在每镜都有独立信息增量、动作证据或受力反馈时才可扩展到11—12镜；日常剧情保持4—6镜。内部时长合计必须等于外层镜号实际时长；每15秒至少推进3次有效状态变化，只设一个最高峰值。
- 微动作可短于1.2秒，但必须嵌入一个合法内部镜头；内部镜头本身默认不少于1.2秒。
- 内部完成v4七大节；第二、三节作为工作层隐藏。

### 第二步：台词、发声与微表情

- 台词字词、顺序和归属逐字保留；未经允许不改标点。
- 长台词允许跨内部镜头连续播放：脸和口型清楚时用 `[SYNC]`，武器、听者或环境插入时用 `[OS-CONTINUE]`。
- 每个内部镜头只写本镜实际承载的台词片段；所有片段按顺序拼接后必须等于原台词，不重复、不漏字。
- 跨镜保持同一声线、语速、呼吸和情绪过程；微表情按句内重音递进，不在切镜后重置。
- 台词超过6秒时，每1.5—3秒至少出现一次力量、位置、能力、伤势或听者反应变化。
- 第一节的【角色账本】只列本镜出现的角色名字；人物状态、说话动机、微表情、身体联动、音量、语速、停顿、呼吸、重音和句尾走向只写在内部镜头的【画面】与【台词与口型】中。

### 第三步：大师镜头与原生切镜

- 每个外层镜号先建立隐藏的 `MASTER_SHOTS_CONSTRAINT_PACKET`，再建立 `INTERNAL_SHOT_COVERAGE_MAP`。
- 先用最相关的1个核心决策，必要时补1—2个，再按条件筛选0—3个不同作用的镜头技巧；允许零技巧。
- 每个内部镜头必须有独立叙事功能和真实机位差异。只改变焦点、轻微下摇或同义描述不算切镜。
- 内部镜头改变机位、景别、焦段或高度时仍须保持轴线、攻击方向、视线和目标点连续。
- 优先覆盖：空间/关系→主要动作→接触或特效证据→受力反应→反转/钩子。

## 用户可见交付

只显示：

- `一、场景与连续性`
- `四、内部镜头`
- `五、生成参数`
- `六、剪辑衔接总表`
- `七、特效对照表`

不得显示隐藏的第二、三节或约束包。第一节使用完整场景字段：大场景、小场景、时间／天气、群像分层、角色账本、角色声音账本、人物专属道具锚定、轴线与运动方向、空间位置与角色站位、首帧参考、尾帧参考；【角色账本】只列本镜角色名字。人物微表情、说话动机、身体联动、发声参数和口型只写在内部镜头的【画面】与【台词与口型】中。镜号末尾追加【角色／武器／伤势】、【光线／声音】、【节奏功能与状态变化】三个汇总字段。第五节只输出比例、【风格词缀】、【固定禁止项】和【负面提示词】；平台模式、原生多镜字样和切镜数量仅作内部路由，不发给用户。完整字段与台词跨镜写法见 `core-workflow.md`。

原生多镜是主交付；第六节必须同时给出真实切点和逐镜拆分回退接口。若平台不支持或生成失败，按内部镜头分别生成后剪辑，不另写重复提示词。

## 验证

分镜写入文件后运行：

```powershell
python scripts/validate_storyboard.py <storyboard.md> --source <source.txt|source.md|source.docx>
python scripts/audit_pacing.py <storyboard.md> --strict
```

结构或台词验证失败必须修复。节奏警告需根据剧情处理，不能为清零警告删去关键动作、台词或情绪。

## 完成标准

- 原始动作、台词、人物、胜负和结果无损；
- 战斗镜号按连续性合并为至少6个真实切镜，通常6—10镜，必要时可到11—12镜，时长合计与标题一致且不超过15秒；日常剧情保持4—6个真实切镜；
- 长台词跨镜声轨连续且片段拼接逐字命中原文；
- 每镜只有一个最高峰值，每15秒至少3次有效状态变化；
- 去掉特效仍看得懂目标、接触/闪避、受力与恢复；
- 内部镜头的机位与功能不重复，切点和声桥可验证；
- 武器、伤势、站位、光源、特效阶段和环境损坏跨镜连续；
- 每个内部镜头都具备独立拆分生成所需的首尾状态。
