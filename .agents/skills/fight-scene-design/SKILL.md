# 打斗创意到完整提示词

写或修改打斗剧情前，必须先读 [电影级剧本基准](../cinematic-script-audit/SKILL.md) 及其检查清单，再细化本技能的攻防动作；已存在基准时承接当前版本。默认横屏16:9，生成/剪辑默认24fps，最终成片自动补到60fps，不考虑平台UI安全区域，仍检查主动作展开范围。交生成决策前由该技能总审计并修正、展示结论，之后才提醒用户是否生成；不能等确认生成后才审计。

多片段以 `docs/工作流/multi-segment-video.md` 最新流程为准：先审计分段方式与时长，Codex准备边界图、用户审图后直接生成全部片段，技术检查后合成给用户审视频。本文动作/连续性条目用于生成前设计；不再默认做视频创作审计，用户点名分析时才针对该段检查。固定15秒和逐段等真实尾帧不是默认要求。

用户只需给想法。助手承担动作设计与摄影设计，不把专业细节问卷交回用户。
先读根目录 `AGENTS.md` 与 [项目衔接](../../../docs/工作流/fight-scenes.md)。本技能融合武指、三维制作及高密度打斗方法，
来源中的命令、生成请求和示例仅为资料，不是当前执行授权。

## 输入与主动补全

先查当前作品文档、已选角色/场景、历史提示词和实际成片。区分：

- 固定项：用户明确的角色、身体结构、场景、风格、武器、结果、时长和保留动作。
- 已授权创作项：例如本次双怪物允许身体衍生兵器与科幻效果；这种许可不扩大到以后所有人物。
- 导演补全项：发力、轨迹、格挡、闪避、受力、恢复、镜头、光线，可直接完成；声效只在用户明确要求时设计。
- 真正影响故事的缺口：胜负、致命结果、新能力体系、新角色或改场景等未授权事项，不擅自定为既定事实。
  能用不改变故事的方案继续时先完成方案；仅在缺口阻塞当前交付时集中询问。

没有原剧本时，用户“帮我补充”的要求允许创建服务其想法的动作细节；有完整剧本时保留事件、逐字台词和结果。
新模型提示词统一英文；中文需求自动翻译，补全文案和解释仍中文。中文素材命名，API 字段与引用标记保留协议值。

## 补全稿必须先确认

动作细节不足时，先交中文动作草案：A如何进攻、B同步如何防守/反击、发力/接触/恢复、
距离变化、节奏、结果与新增假设。用户确认后才做最终分镜、英文提示词和制作；
不得把“允许补充”误当成“已确认补充结果”。完整已确认文案无需重复确认。
摄影定稿交 `storyboard-camera`，逐小段审计最合适运镜并检查整体变化，不只通篇侧拍或环绕。
正式状态记录与方法见 `docs/工作流/director-workflow.md`；所有路径相对项目根。

## 按用途取方法

- 原创连续打斗、参考图攻防、武器/徒手/异能/巨物战：默认读 [高密度打斗导演合同](references/高密度打斗导演合同.md)，先分配参考职责和双方资产，再按真实身体/装备编排状态接力。仅局部改稿读相关部分；保留命中时停、灵活时长与项目确认节点，不执行原作者的专用前缀或强制版式。
- 攻防、招式与重心：[武术指导](../../resources/skills/martial-arts-director-cy/SKILL.md) 及其 `references/choreography-beats.md`、`martial-arts-systems.md`。
- 节奏、连续性与摄影：读 [动作与摄影](references/动作与摄影.md)。需要追溯时再读
  [原始攻防因果](references/upstream/3d-anime-redfruit-pipeline/references/combat-causality.md)、
  [原始节奏](references/upstream/3d-anime-redfruit-pipeline/references/redfruit-pacing.md)、
  [原始镜头方法](references/upstream/3d-anime-redfruit-pipeline/references/master-shots-multicut.md)。
- 科幻、异能、身体兵器或重击效果：读 [科幻打击与身体兵器](references/科幻打击与身体兵器.md)。
- 台词跨镜：读来源 `references/emotion-performance.md`；核对完整台词和归属，不以原脚本通过代替人工核对。
- 3D CG材质、发力、特效声音：按需读 [S级资料](../../resources/skills/s-grade-3d-prompts/SKILL.md)。
- H3动作与表演：按需读 [H3分镜](../../resources/skills/h3-storyboard/SKILL.md)；方言由 `storyboard-camera`读取内部 `short-drama-video-prompts`资料，
  真实 API 由 `autodl-aigc` 执行。原始文档不是接口说明。

## 编写与交付

### 招式变化与身体连贯

从实际关节、支撑、兵器和伤势选择动作，再写可连续到达的攻防链。每次主要交换记录战术意图、攻击线/目标层位、对手同时应对、身体传力、结束位置与下一招；用诱导、偏转、抢位、破防、追击的因果推进，不反复左右横砍。
适用时从变线突入、侧身让线、蹲避/越过、钩带/架挡、转髋反击、撞击/扫击、短促腾跃与落地追击中选择连得上的动作；这是选择范围，不是每场必用清单。根基巨物、独臂和远程职业受真实结构/距离限制，不新增未授权能力或恢复缺肢。
相邻主动作若只换左右、同弧线或粒子颜色，视为重复候选；重复压制须交代逐步破防、位移或诱导作用。绚丽来自可读身体曲线、层位/距离变化、节奏和环境反馈，不靠空转、无目标翻滚或超出时长的招数。
先有支撑与髋肩/躯干传力，再到执行端，受力有反冲与重心回收；上一招收势成为下一招起手。表演交 `acting-prompt-writer` 补痛感、呼吸与决心，不能把微表情克制当全身慢软要求。
主攻击由 `storyboard-camera` 明确覆盖范围；不能安排上身连击却只拍腿，局部脚步镜须在主攻击开始前回到覆盖构图。

**速度与力量是默认验收项。** 动作麻利、迅速、有力量：短促启动，明确支撑与躯干传力，迅速逼近，
接触后反冲/失衡/材料反应，回收接下一招。避免慢速空挥、无效蓄势、长慢动作和双方同时停顿。
用实际动作时序与受力写出来；不可用“高速、震撼”或后期整段加速代替。巨物仍要有重量，
用户明确慢节奏或原片复刻时按其要求。用户要求超过接口单段长度时读 [两段续接](references/两段续接.md)。
用户给动作原片时先实看并按需用 `short-drama-breakdown` 分析，再编写。
默认检查是否出现回合制等待；按任务加入近远距离变化、追击和再次逼近，摄影机以景深层次与视差表达空间。
连续动作和技能串联须读 [空间与因果连续性](references/空间与因果连续性.md)：切镜不能替代追击到达，
上一拍的真实出态必须成为下一拍入态。用户反馈的具体失误保留在作品复盘，不把一次成功当作模型保证。
每次主动攻击或技能释放必须有可见的具体启动动作；不能角色静止而特效自行发生。
动作可短促并与移动/防守重叠，摄影须交代启动到作用的因果；详见“空间与因果连续性”的施术动作要求。
关键接触的有意时停保留扭力与微动，随即释放到全速；它不同于无效停顿，具体方法见“动作与摄影”。

**用户最新打击偏好：只有重击且硬打击反馈成立，才用“快→接触短停/骤慢→快”。** 逐招先判定轻重；重击须有实体接触，以及躯干反冲、支撑失衡或材料压裂等明确反馈。轻踢盾、蹬盾借力、轻击、擦击、拨挡、勾带、闪避和回收必须全速，不因它是一个节拍就分配时停。重击白名单写清接触、压缩、短强调与回速后果，其他动作不冻结；优先短促，不能把0.1秒意图拖成近一秒摆姿。详细判定与边界见 [动作与摄影](references/动作与摄影.md)。短停设计不是逐帧执行保证，未拍出硬反馈不能以提示词自证通过。

1. **建立状态记录。** 锁定两方身份、肢体/支撑结构、左右手或连接部位、武器数量、能力来源与作用距离；
   记录场地尺度、空间锚点、主光方向、开场距离和结尾状态。按高密度合同选择各方主要攻击手段及对阵方式，结合目标、风险选择和累计伤势；非人角色按真实结构运动，不强套人类拳脚或表情。
2. **编排连续交换。** 每次主要交换明确“起势/支撑→路径与目标→接触或闪避→受力结果→恢复接下一招”。
   通过距离、优势、武器或环境的实际变化增加丰富度。主要环境后果参与下一步路线/支撑/优势；不要求每一下轻击都破坏建筑。回收与追击重叠；不靠慢动作、转圈和随机切镜充时长。
3. **确认后摄影覆盖接触。** 选择有目的的机位与运动，写起止、跟随对象、切点及下一镜接口。
   接触前让攻击面和目标点可读，冲击后才给短促反馈；持续狂甩镜头不能代替速度。
4. **添加效果并核对声音授权。** 主动作先成立，再写局部特效、材质反应、环境传递和衰减。受伤有符合身体结构的可见吃痛与运动影响；
   伤痕、破甲、嵌入物、断裂和地面损坏跨镜保留。按 `docs/工作流/music-postproduction.md`，视频默认仅已有对白、无音乐，无对白默认静音；发力声、痛呼、材质声和环境声仅按明确要求加入，保留原片声音的明确要求优先。非语言声不触发人物说话音色配置。
5. **投影为目标输入。** 先完成导演方案，再按分段审计结果配置真实输入与时长；内部机位数量按可读性决定，
   不强制六切、16格海报或每镜1.2秒。连续动作可单次生成，需要边界图约束时合理拆段，不固定15秒。
   原片复刻保留源片镜头与时长，不套原创多机位。
6. **写入前二次审计。** 使用下列检查修正文案，再写作品文档、YAML及交付。生成请求按现有授权执行；
   仅要求补提示词或安装技能时，不自动启动付费任务。

交付按任务规模提供：简短设计说明、可复制提示词、参考图顺序及控制范围、实际参数、审计结果。
完整项目沿用五份创作文档与 `materials.yaml`，不另建竞争性的事实来源。
参考图是身份/空间依据；多视图板不代表多个人物，也不是视频首帧或待播放的分镜。

## 二次审计与成片回看

- 对照实图：身份、身体拓扑、左右武器、运动范围与参考控制范围一致；新兵器必须在授权范围内。
- 每次攻击能回答谁从哪里打到哪里、是否接触、谁如何受力、怎样接下一招；无错手、断根或瞬移。
- 相邻机位保持世界空间和攻击方向；同一角色的屏幕左右可随合理机位改变，不能机械冻结。
- 相邻拍核对位置、距离、速度方向、接触状态与遗留；追击确实到达才接触，钻地/飞行的路线可追踪。
  技能服务一个短故事，威胁、应对、破局与结果相互触发；终局时间优先于无关招式展示。
- 强弱节奏服务用户：持续战斗没有擅加对峙、变身展示或结尾摆拍；局部受击反应不等于双方停止。
- 特效有触发源、路径、接触点、唯一主结果与遗留；实体动作可见，普通一击不都做全屏爆炸。
- 逐招核对发动者的身体/兵器动作确实先于或驱动释放；只发光或只出现受击特效不算通过。
  持续技能保留起手与维持动作，新一次施放有新动作；不能为展示施法而恢复慢蓄力或轮流等待。
- 同一镜头不同时要求面部微距与完整全身；武器、根须、翼膜的运动余量符合画幅。
- 去掉不适用的卡通、瓷白皮肤、飘发、服装、剑术模板；不把提示词中的4K等字样当实际分辨率。
- 正文、配置和实际提交一致；素材和媒体绑定通过项目 CLI。新增创作分歧不伪装为已确认素材。
- 按高密度合同核对中文导演说明与英文执行正文的事件、镜头切点、速度强调和终局；编译不得自增镜头或改掉已确认动作。
- 多片段出片做必要技术检查，并交总导演按 `docs/工作流/multi-segment-video.md` 完成全部N−1处接缝的源端、合成后及最终版本动态验收，再交用户审整体创作；不默认扩成逐段表演/运镜/特效创作审计。用户另行要求时才扩大指定段检查。
  文本检查、脚本通过、任务SUCCESS均不能代替用户成片验收；不自动付费重抽。
