# 视频工具

人物声音档案和试听队列由 `tools/角色.py` 管理，见 [人物与声音流程](../../docs/工作流/character-voice.md)。此工具只管理档案/离线校验；参考音频合成由现有AutoDL客户端执行，图像到创意音色设计尚未接入。

在 E:\AutoDL 中使用 `.venv\Scripts\python.exe` 执行下列脚本。作品入口为 `projects/<作品>/project.yaml`；素材、配置、结果均放该作品内。程序共用本机 FFmpeg，不提交收费生成任务。

已登记作品的输入和输出必须属于同一作品，剪辑配置及全部片段不能混用不同作品。迁移过的旧路径先解析到当前路径。没有 `project.yaml` 的独立临时文件仍可使用这些工具。

| 入口 | 用途 |
|---|---|
| 剪辑.py 配置.yaml --output 成片.mp4 | 裁切、局部变速、音画同步拼接；默认24fps，记录源区间和全部接缝 |
| 抽帧.py 视频.mp4 --output 新目录 --interval 1 | 一次 FFmpeg 进程批量抽帧；`--frame 123` 抽零起算精确解码帧 |
| 补帧.py 视频.mp4 | 低于目标用RIFE，等于目标检查后复用，高于目标另存转帧率副本；默认60fps，保留原片和声音 |
| 移动水印.py 视频.mp4 | 默认 @CallMeQueenAI，半透明文字沿边缘移动；另存，不覆盖干净母版 |
| 审片.py prepare --project 作品目录 --video 视频.mp4 | 探测、完整解码、建立会话；可重复 --video 增加源片/合成/最终版 |
| 审片.py serve 审片会话.json | 启动127.0.0.1网页，打印含会话令牌的本地链接 |
| 音乐.py capabilities | 查看真实能力；专用 AI 音乐模型未接入 |
| 音乐.py create 音符配置.yaml --output 器乐草稿.wav | 本地音符合成器乐动机，用于配乐预演，不冒充 AI 电影配乐 |
| 音乐.py import 源音频 --manifest materials.yaml --asset-id MUSIC-01 --name 配乐-版本01.wav --provenance 来源说明 | 导入/引用音乐资产，标记待检查 |
| 音乐.py validate 配乐方案.yaml | 检查时间线哈希、素材、完整音乐/留白覆盖、淡变及源长度 |
| 音乐.py mix 配乐方案.yaml --output 配乐版.mp4 | 淡变、按对白区间压低配乐、合成真正的混合音轨；视频码流复制 |

水印可选 `--text`、`--opacity`、`--period`（完整绕行秒数）、`--margin`、`--font-size`、`--font`、`--output`。视频必须编码，音轨复制；不声称视频无损。90度倍数旋转按实际显示画布放置水印，保留显示方向和像素比例；其他旋转与HDR输入暂不支持。先剪辑/混音，再补帧，按需要加水印，最后实际审片；本次开发不会批量处理旧成片。

补帧入口的复用、转帧率与RIFE导出均检查实际帧数、帧率、时间戳、音轨和完整解码。转帧率副本默认名为 `原名-转帧率60帧.mp4`（特殊音轨等使用MKV），重复运行另存版本；它需要视频重编码，不是RIFE插帧。相等或较高帧率分支不依赖RIFE运行环境。抽帧先在临时目录完成，成功后才发布输出目录，失败可修正参数并用同一路径重试。

补帧/转帧率保留兼容MP4的音轨和mov_text字幕；其他字幕、附件或特殊音轨使用MKV。mov_text与必须MKV的轨道组合会在视频处理前拒绝，需先明确兼容方案，不静默丢轨或转码。已达目标帧率时核验并复用源容器。

水印及混音发布校验比较实际显示画布、像素比例、解码帧数和逐帧相对时间戳；只允许容器时间基造成的量化误差，不能通过修改平均帧率标签掩盖丢帧或变速。MKV与MP4的平均帧率标签略有差异时，实际帧时间线一致仍可发布。

剪辑配置与各片段、水印、抽帧及补帧输入在首次读取前捕获为私有字节快照；探测、编码、合音轨和发布校验使用同一版本，记录保留原路径及捕获时的SHA-256。重复输入复用快照，捕获期间变化或发布前原路径内容变化时拒绝发布；源文件临时被替换后恢复，也不会把替换版画面或声音混入结果。单独保存的补帧计划绑定源哈希，之后导出必须匹配该版本，否则要求重新探测。快照放系统临时目录，正常结束和可捕获异常均清理，不归档冗余媒体；操作系统强制终止进程时无法保证自动清理，不能把残留临时输入当成成片。

## 剪辑配置

路径相对配置文件；不同尺寸或像素比例须先确定缩放/裁切，工具不擅自选构图。相同的非方形像素比例会保留，不把画面压成方形像素。

```yaml
fps: 24
clips:
  - path: ../04-输出/原始片段/片段01.mp4
    in_seconds: 0.2
    out_seconds: 8.4
    speed: 1
```

单音轨片段默认保留该轨；多音轨片段必须逐项填写 `audio_track`（音轨零起算序号，例如第二条音轨为 `audio_track: 1`），未指定时拒绝剪辑，避免误选非默认对白。当前剪辑输出一条同步后的立体声音轨；选择记录写入剪辑记录，原文件及其他原始音轨保持不变。需要同时保留多条独立音轨时，先明确每轨处理方案。

裁切按实际解码帧确定源区间，记录请求秒数、实际秒数和零起算帧范围；音频先按PTS恢复首偏移及内部静音，再应用同一时间映射。每段尾部统一到输出帧网格，发布前检查实际帧数和整条音轨覆盖。音频变速需要本机FFmpeg包含 `rubberband` 滤镜，缺少时明确失败，不退回已知有同步问题的处理链。变速通过重采样时间轴及反向pitch补偿保持原音高；工作采样率不低于源采样率及其速度倍数，恢复音高后才输出48kHz，避免快速处理中提前截掉高频。记录实际音频速度与工作采样率。极端变速仍有分析窗造成的短暂瞬态误差，技术检查不保证任意素材逐采样瞬态完全一致，实际听音和动态审片保持独立待验。

输出是待审剪辑预览。接缝记录所有 N−1 处，不能凭生成了文件就称接缝通过。`审片.py prepare` 可带 `--edit-record` 绑定当前合成的剪辑记录。源片两侧至少各1秒、原生合成、最终处理版都需实际观看；从版本菜单切换并按各自时间坐标记结论。

新导出的剪辑、水印、混音及器乐制作记录保留完整媒体文件名，例如 `成片.mp4.剪辑记录.json` 与 `成片.mkv.剪辑记录.json` 分别绑定各自版本。导出前检查记录路径，发布时排他写入；即使媒体暂不存在，已有记录也不能被覆盖，需另存版本。旧格式记录保留原文，仍可通过 `--edit-record` 显式读取。

## 音乐配置

使用 [配乐方案模板](../../templates/short-drama/配乐方案.yaml)。完整剪辑的秒坐标，入点包含、出点不包含。`materials_manifest` 与视频路径相对方案；音频路径相对 materials。

cue 至少包含 cue_id、start_seconds、end_seconds、purpose、entry_trigger、exit_trigger、instrumentation、source_asset_id、source_in_seconds、gain_db、fade_in_seconds、fade_out_seconds。所有音乐外区间填写 no_music_regions（起止与 reason）。重叠 cue 写 cross_cue_transition 说明。增删/移动/替换 cue 直接编辑 YAML，重新 validate/mix，另存版本。

```yaml
dialogue_ducking:
  method: regions
  gain_db: -12
  regions:
    - {start_seconds: 3.0, end_seconds: 5.2}
```

对白区间是全片坐标，80ms 音量过渡；未检测或核实对白时间时不能称避让已完成。旧片已有 BGM 且无干净对白底轨时拒绝叠乐。音频必须经实际检查后在 materials 中登记 ready 和 SHA-256。技术解码通过不等于音乐连贯、对白可懂或用户接受。

本地器乐草稿配置：`duration_seconds: 8`，`notes` 为 `{start_seconds: 0, duration_seconds: 2, midi_note: 60, gain: 0.12}` 列表。无歌词、无人声；高质量配乐可导入已制作音乐。专用音乐模型需后续接入真实服务，不能把此合成器称作该功能。

## 网页审片

白模入口：`白模.py validate/inspect/render/verify-cuts/check-bundle/review`，详见 [白模制作与验收](../../docs/工作流/白模制作与验收.md) 和 [YAML模板](../../templates/whitebox-retargeting/白模计划.yaml)。检查在新Blender进程中加载已保存工程，绑定实际SHA-256；逐帧检查已声明相机、主体和接触。`render`另存审片/送模两版及证据，`review`复用下方网页。白模预览默认无声，不代替保留原声的正式引导。未实际动态观看或试听不标通过。

直接串流现有视频，支持 Range、切换版本、循环区间、变速、精确静帧、带时间码的问题和结论。原始记录绑定 SHA-256；源文件变化后会话拒绝继续使用旧结果。技术、静帧、动态、听音、用户认可分开，不自动互相推断。浏览器拖动不能保证帧精度，精确静帧由后端解码。

新审片记录的时间码仅接受有限数值，拒绝字符串和布尔值；历史数字字符串仍能显示，其他无效历史时间码明确标识并保留原记录。精确帧缓存按帧跨进程加锁，完整 PNG 校验和解码通过后才原子发布；写入中断不会发布半帧，已存在的损坏缓存在下次请求时重建。

审片直接读取原媒体，不复制整段视频。Windows 读取句柄从探测、完整解码、哈希校验一直保持到抽帧、串流或记录保存完成，允许多个读取者，同时禁止外部写入及替换；已有写入句柄时明确拒绝并提示重试。此无复制保护目前仅支持 Windows，其他平台拒绝审片，不降级为普通读取或仅协作式文件锁。PNG 内嵌缓存版本、源 SHA-256 和帧号；缺失或不匹配时重建，避免复用旧服务可能留下的错误帧。

服务仅监听本机，需随机会话令牌，媒体只从当前作品的显式清单读取。停止服务按 Ctrl+C。历史脚本不作为当前入口，不沿用它们复制成片或猜测验收的行为。
